这篇是把真实项目里的内容收进知识库的入口。截图、菜单路径、报错原文、单据编号、SQL、日志、客户环境差异、临时处理办法，都先按这套格式收集，后续再拆到模块教程、FAQ、问题案例、SQL 查询包或实施模板里。

目标不是把所有材料立刻写成正式文章，而是先保住上下文。真实环境里的关键信息一旦丢掉，后面只剩一句“当时处理过”，就很难复盘、培训和复用。

## 一、什么内容先放这里

| 内容 | 示例 | 后续去向 |
| --- | --- | --- |
| 菜单路径 | 生产制造 -> 车间管理 -> 报工处理 | 对应模块教程 |
| 截图 | 报错截图、配置截图、单据状态截图 | 问题案例或操作手册 |
| 报错原文 | 保存失败、接口返回、插件堆栈、权限提示 | FAQ 或运维问题库 |
| 单据编号 | 生产订单、采购入库、应收单、凭证号 | SQL 或问题排查 |
| SQL | 已验证查询、临时排查语句、字段确认语句 | 数据模型与 SQL |
| 接口报文 | 请求、响应、外部单号、幂等键 | 接口与集成 |
| 版本环境 | 产品版本、补丁、组织、账套、模块授权 | 环境发布或问题记录 |
| 处理过程 | 临时绕行、最终修复、回归结果 | 运维案例库 |
| 培训问答 | 用户反复问的问题、口径解释 | 常见问题库 |
| 客户差异 | 行业特殊流程、二开字段、审批差异 | 模块专题或实施文档 |

## 二、最小收集规则

每条真实内容至少保留：

- 发生时间。
- 发生环境：生产、测试、预生产、本地。
- 模块和菜单路径。
- 业务对象：单据类型、单据编号、物料、客户、供应商、组织。
- 现象：用户看到什么，系统提示什么。
- 期望：用户认为应该怎样。
- 证据：截图、报错原文、日志、SQL 结果、接口报文。
- 当前处理状态：待确认、处理中、已绕行、已修复、待复盘。
- 后续去向：FAQ、案例、SQL、模块教程、实施模板。

## 三、脱敏规则

放入知识库前先处理敏感信息。

| 信息 | 处理方式 |
| --- | --- |
| 客户名称 | 用 `客户A`、`集团B`、`工厂C` 替代 |
| 真实人员 | 用岗位代替，例如 `成本会计`、`仓库主管` |
| 手机、邮箱、地址 | 删除或打码 |
| 金额 | 可保留比例、差异方向；真实金额按需要改成样例 |
| 单据编号 | 内部库可保留，公开前需替换成样例编号 |
| 数据库连接 | 删除服务器、账号、密码、Token |
| 接口密钥 | 禁止进入知识库正文 |
| 截图 | 遮挡客户名、账号、手机号、地址、合同号 |

判断标准很简单：这条内容给新人学习和排查有价值，但不能让外部人通过它识别客户、人员、合同、价格和系统密钥。

## 六、截图命名建议

截图不要叫 `1.png`、`新建图片.png`，后面一定找不到。

建议命名：

```text
YYYYMMDD-模块-对象-现象-序号.png
```

示例：

```text
20260701-制造-生产订单-MES报工未回写-01.png
20260701-供应链-销售退货-RMA质检状态异常-01.png
20260701-财务-应收总账-往来差异-01.png
20260701-接口-WMS回传-重复生成入库单-01.png
```

## 八、沉淀状态流

```text
临时材料
  -> 00_inbox 收集
  -> 补齐证据和脱敏
  -> 判断类型
  -> FAQ / 案例 / 模块教程 / SQL 包 / 实施模板
  -> 回链到知识地图和学习路径
  -> 标记 stable
```

每周整理时只做三件事：

1. 把没有上下文的材料补齐最小信息。
2. 把高频问题拆到 FAQ 或问题案例。
3. 把已经验证过的 SQL、菜单路径、处理方法反补到正式专题。

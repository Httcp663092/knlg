WMS 集成不是“把出入库接口调通”就结束。真正的难点在上线后：WMS 已收货但金蝶没有入库，金蝶已经审核但 WMS 没有扣库存，接口超时后重复推单，盘点差异无法解释，存货核算发现库存数量和金额都不可信。

这篇把 WMS 和金蝶的出入库、状态回写、库存余额、异常补偿和月末对账整理成一套可落地的方案。

## 一、WMS 集成主线

```text
金蝶基础资料
  -> 同步到 WMS
  -> 金蝶业务单据下发 WMS
  -> WMS 收货 / 上架 / 拣货 / 复核 / 发货 / 盘点
  -> WMS 回传执行结果
  -> 金蝶生成或更新出入库单
  -> 库存余额、批号、序列号、成本和凭证
  -> 月末接口、库存、财务对账
```

先定清楚“谁是主系统”。同一个对象不能两边都随便改，否则后面只能靠人工对账。

| 对象 | 建议主系统 | 说明 |
| --- | --- | --- |
| 物料、客户、供应商、组织、仓库 | 金蝶 | 业务和财务口径来源 |
| 库位、容器、波次、拣货任务 | WMS | 仓内作业细节来源 |
| 采购订单、销售订单、生产订单 | 金蝶 | 业务源头 |
| 收货实绩、发货实绩、盘点实绩 | WMS | 现场执行结果 |
| 库存账、成本账、凭证 | 金蝶 | 财务和管理报表来源 |

## 二、典型业务场景

| 场景 | 金蝶发起 | WMS 执行 | 回写金蝶 | 对账重点 |
| --- | --- | --- | --- | --- |
| 采购入库 | 采购订单或收料通知 | 收货、质检、上架 | 采购入库单 | 数量、批号、供应商、到货差异 |
| 销售出库 | 销售订单或发货通知 | 拣货、复核、发运 | 销售出库单 | 客户、物料、批号、实际发货数量 |
| 生产领料 | 生产订单或领料单 | 拣料、发料 | 生产领料单 | 工单、用量、替代料、超领 |
| 完工入库 | 生产汇报或完工通知 | 收货、上架 | 生产入库单 | 工单、合格数量、不良数量 |
| 调拨 | 调拨申请或直接调拨单 | 出库、运输、入库 | 调拨出入库 | 在途、收发组织、仓库 |
| 其他出入库 | 手工业务单据 | 仓库执行 | 其他出入库单 | 原因、审批、费用归属 |
| 盘点 | 盘点计划 | 初盘、复盘、差异确认 | 盘盈盘亏单 | 账实差异和审批 |
| 退货 | 退货通知 | 收货、质检、上架或隔离 | 销售退货或采购退料 | 质量结论、库存状态 |

## 三、接口字段底线

不管技术方案是 WebAPI、集成平台、中间库还是消息队列，下面这些字段都不能缺。

| 字段 | 用途 |
| --- | --- |
| 外部单号 / WMS 单号 | 幂等和对账 |
| 金蝶源单号 | 追溯订单、通知单、生产订单 |
| 金蝶目标单号 | 追溯最终出入库单 |
| 组织、仓库、库位 | 确认库存归属 |
| 物料、批号、序列号、辅助属性 | 实物追溯 |
| 数量、单位、换算率 | 防止数量偏差 |
| 库存状态 | 合格、待检、冻结、不良、报废 |
| 业务日期 | 影响期间、成本和月结 |
| 状态 | 已接收、处理中、成功、失败、已补偿 |
| 错误信息 | 用于人工处理和知识沉淀 |
| 版本号或更新时间 | 防止旧状态覆盖新状态 |

## 四、状态机设计

WMS 集成不要只设计成功和失败。至少要有可追踪的中间状态。

```text
待下发
  -> 已下发
  -> WMS 已接收
  -> WMS 作业中
  -> WMS 已完成
  -> 金蝶已回写
  -> 金蝶已审核
  -> 已对账
```

异常分支：

```text
下发失败
回写失败
金蝶校验失败
重复请求
部分成功
人工挂起
已补偿
已作废
```

| 状态 | 允许动作 | 不允许动作 |
| --- | --- | --- |
| 待下发 | 下发、取消 | 人工改 WMS 实绩 |
| WMS 作业中 | 查询状态、撤销未开始作业 | 金蝶强行改数量 |
| WMS 已完成 | 回写金蝶、补传附件 | 重复生成出入库 |
| 金蝶回写失败 | 修数据、重试、人工补偿 | 直接关单 |
| 已对账 | 归档、月结 | 再次变更业务数量 |

## 五、幂等和防重复

重复单是 WMS 集成的高频事故。一次网络超时，调用方不知道金蝶是否成功，就可能再推一次。

| 规则 | 做法 |
| --- | --- |
| 幂等键唯一 | 用外部系统编码 + 外部单号 + 行号 + 业务类型 |
| 先查后写 | 回写前先查金蝶是否已存在目标单 |
| 结果可查询 | 接口返回处理中时，外部系统能按幂等键查询结果 |
| 重试不改业务 | 重试只能补同一笔业务，不能生成新单 |
| 人工补偿留痕 | 手工补单必须记录原外部单号和原因 |

## 六、库存一致性对账

库存一致性不能只看总数量。至少分四层。

| 层级 | 对账对象 | 判断标准 |
| --- | --- | --- |
| 单据层 | 金蝶单据和 WMS 作业单 | 单号、行号、数量、状态一致 |
| 库存层 | 金蝶即时库存和 WMS 库存 | 组织、仓库、物料、批号、库存状态一致 |
| 在途层 | 已出未入、已发未收、作业中 | 在途数量有来源、有责任、有预计完成时间 |
| 财务层 | 库存数量、存货成本、凭证 | 数量和金额能进入月结和存货核算 |

### 对账频率

| 频率 | 对账内容 |
| --- | --- |
| 实时 | 接口失败、重复单、回写失败 |
| 每日 | 出入库单据数量、WMS 已完成未回写、金蝶已下发未执行 |
| 每周 | 批号、序列号、库存状态、在途 |
| 月末 | 即时库存、存货收发存、盘点差异、成本和凭证 |

## 七、补偿机制

补偿不是“失败了再点一次”。补偿要先判断失败点，再决定补哪个系统。

| 失败点 | 现象 | 补偿方式 |
| --- | --- | --- |
| 金蝶下发 WMS 失败 | WMS 没有任务 | 修主数据、权限或接口后重新下发 |
| WMS 已执行但回写失败 | WMS 有实绩，金蝶没有出入库 | 按原 WMS 单号重试回写 |
| 金蝶生成单据但未审核 | 金蝶有草稿或暂存单 | 修业务校验后审核 |
| 接口超时但实际成功 | 调用方认为失败，金蝶已有单 | 按幂等键查询，返回已成功 |
| 部分行成功 | 部分物料已入库或出库 | 逐行补偿，避免整单重复 |
| 业务取消 | WMS 未执行或已执行 | 未执行可取消，已执行要做反向业务 |
| 人工线下处理 | 仓库已经发货或收货 | 补录单据并标记人工补偿 |

## 八、禁止用库存调整掩盖接口问题

库存调整只能处理盘盈盘亏或经审批的账实差异，不能拿来消化接口失败。

| 不建议做法 | 后果 |
| --- | --- |
| WMS 已出库，金蝶没出库，直接做盘亏 | 销售出库、应收、成本都断链 |
| 金蝶多出一张出库，用其他入库冲回 | 客户、订单、成本和毛利失真 |
| 接口重复入库后手工改库存 | 采购、应付、暂估和成本都可能错 |
| 月末用一张调整单抹平差异 | 下月继续错，无法追根因 |

正确做法是先恢复业务链：源单、目标单、接口日志、实物、财务凭证都要能互相追溯。

## 九、常见异常排查表

| 现象 | 可能原因 | 排查路径 | 处理 |
| --- | --- | --- | --- |
| WMS 已收货，金蝶没有入库 | 回写失败、金蝶校验失败、组织或物料映射错误 | 查 WMS 回传日志、金蝶接口响应、采购源单 | 修映射后按原单重试 |
| 金蝶有入库，WMS 没有库存 | 金蝶人工补单、WMS 未接收、仓库未上架 | 查金蝶单据来源、WMS 作业单、上架记录 | 补 WMS 作业或冲销错误单 |
| 销售出库重复 | 超时重试没有幂等 | 查外部单号、金蝶目标单、接口调用次数 | 建唯一幂等键并清理重复单 |
| 批号不一致 | WMS 拣货批号和金蝶预分配批号不同 | 查批号规则、拣货策略、回写字段 | 以实发批号回写并校验 |
| 库存状态错误 | 待检、冻结、不良状态映射不一致 | 查状态字典和接口字段 | 统一库存状态映射 |
| 月末数量一致金额不一致 | 成本核算未完成、调整单没有凭证 | 查存货核算、成本调整、凭证生成 | 完成核算后再对账 |
| 服务站库存对不上 | WMS 管实物，金蝶未建服务站仓 | 查仓库映射和调拨记录 | 建服务站仓或寄售台账 |

| 检查项 | 说明 |
| --- | --- |
| 主数据冻结窗口 | 物料、仓库、客户、供应商、批号规则切换前冻结 |
| 期初库存导入 | 金蝶和 WMS 同一时点、同一维度、同一状态 |
| 未完成单据清理 | 已下发未执行、已执行未回写、在途单据要清单化 |

| 接口压测 | 覆盖高峰出入库、批量回写、重试和查询 |
| 回退方案 | 接口停摆时如何手工发货、补单、对账 |
| 权限和账号 | 接口账号、仓库人员、审批人员权限可用 |
| 监控看板 | 失败数、积压数、重复数、超时数、未对账数 |

## 十一、监控指标

| 指标 | 含义 | 风险信号 |
| --- | --- | --- |
| 接口成功率 | 成功调用 / 总调用 | 低于约定阈值 |
| 平均回写时长 | WMS 完成到金蝶生成单据 | 持续变长 |
| 待补偿数量 | 失败或人工挂起的单据 | 日积月累 |
| 重复请求数量 | 同一幂等键重复调用 | 幂等规则薄弱 |
| 已完成未回写 | WMS 完成但金蝶未完成 | 库存和财务断链 |
| 已下发未执行 | 金蝶已下发但 WMS 未处理 | 仓库作业积压 |
| 库存差异行数 | 金蝶和 WMS 库存不一致行数 | 月结风险 |

## 十三、三类典型案例

### 案例 1：采购收货回写失败

现象：WMS 已经收货上架，采购人员在金蝶看不到采购入库单，应付和存货都没有增加。

排查：

1. 查 WMS 收货单号和回写时间。
2. 查接口日志是否返回物料、仓库、供应商或采购订单错误。
3. 查金蝶采购订单是否关闭、数量是否超收、组织是否一致。
4. 查是否已经生成草稿单但未审核。

处理：

- 修正主数据或源单状态。
- 按原 WMS 单号重试回写。
- 如果已经人工补单，必须把 WMS 单号补到来源字段，防止再次回写生成重复单。

### 案例 2：销售出库接口超时导致重复发货

现象：WMS 第一次回写超时，第二次重试后金蝶生成两张销售出库单。

排查：

1. 查两张销售出库单的来源外部单号。
2. 查接口是否以请求流水号而不是业务单号做唯一键。
3. 查调用方超时后是否先查询结果。

处理：

- 以 WMS 出库单号 + 行号 + 业务类型作为幂等键。
- 重试前先查金蝶是否已有目标单。
- 对重复出库按业务规则冲销或作废，并复核库存成本和应收。

### 案例 3：月末 WMS 和金蝶库存数量一致但状态不一致

现象：同一物料总数量一致，但 WMS 有待检和冻结库存，金蝶全部是合格库存。

排查：

1. 查库存状态映射表。
2. 查收货质检、冻结解冻、质量判定是否回写。
3. 查金蝶库存报表是否按库存状态展开。

处理：

- 补齐库存状态字段。
- 对历史数据按盘点或状态调整流程处理。
- 后续月末对账必须按组织、仓库、物料、批号、库存状态五个维度展开。

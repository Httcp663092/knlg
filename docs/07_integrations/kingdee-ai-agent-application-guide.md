本页把“金蝶 AI”按项目现场能理解、能落地、能验收的方式整理：AI 管理助手是什么、智能体能做什么、财务和供应链怎么用、怎样接知识库和工具、权限审计怎么做，以及哪些场景必须保留人工确认。

一句话理解：

```text
金蝶 AI 的项目价值，不是把 ERP 旁边放一个聊天窗口，而是让 AI 在权限、数据、知识、流程和审计约束下协助完成业务任务。
```

## 二、先把几个词讲清楚

| 名词 | 通俗理解 | 项目里要关注什么 |
| --- | --- | --- |
| AI 管理助手 | 面向员工、专员和管理者的智能入口 | 能问什么、能做什么、权限怎么继承 |
| 智能体 Agent | 能理解指令、规划步骤、调用工具并返回结果的业务角色 | 是否有工具权限、审批点、日志和失败处理 |
| Agent Builder | 用来创建和编排智能体的能力 | 谁能创建、能调用哪些工具、怎么测试 |
| Skill Builder | 把提示词、插件、任务流和工具组合成稳定技能 | 技能输入输出、版本、回归测试 |
| Knowledge Builder | 管理企业知识库和 RAG 检索 | 文档权限、切分、更新、引用来源 |
| RAG | 先检索企业知识，再让模型回答 | 防止凭空编答案，要求显示来源 |
| MCP/API 工具 | 智能体可调用的外部系统能力 | 工具鉴权、幂等、审批、审计 |

## 三、金蝶 AI 的分层架构

可以按七层理解：

```text
用户入口
  -> AI 管理助手
  -> 智能体/技能
  -> 企业知识库和 RAG
  -> ERP/SaaS/API/MCP 工具
  -> 权限、脱敏、审计和安全网关
  -> 业务结果和人工确认
```

| 层级 | 例子 | 关键问题 |
| --- | --- | --- |
| 用户入口 | 云之家、PC 端、移动端、业务页面入口 | 用户是谁，当前角色和组织是什么 |
| AI 管理助手 | 财务助手、采购助手、数据助手、开发助手 | 负责回答还是负责执行 |
| 智能体/技能 | 报销审核、问数分析、供应商风险、知识问答 | 是否有明确边界和成功标准 |
| 知识库 | 制度、操作手册、项目文档、FAQ | 资料是否最新，权限是否隔离 |
| 工具调用 | 查询单据、创建任务、发起审批、调用接口 | 是否需要人工确认和幂等键 |
| 治理安全 | 权限、脱敏、注入防范、日志、审计 | 是否可追踪、可回放、可问责 |
| 业务结果 | 报告、建议、草稿、审批意见、异常清单 | 结果是否可解释、可复核 |

## 四、AI 场景分类

不要一上来就说“全公司都要 AI”。先按场景类型拆开。

| 类型 | 适合场景 | 风险重点 |
| --- | --- | --- |
| 问答型 | 制度问答、操作手册、实施 FAQ、客服答疑 | 资料来源、权限、过期内容 |
| 生成型 | 财务分析报告、会议纪要、邮件、培训材料 | 编造、语气、审批 |
| 分析型 | ChatBI、指标解释、异常归因、趋势分析 | 口径、数据权限、可复核 |
| 审核型 | 报销附件、发票、合同条款、异常费用 | 误判、责任边界、人工复核 |
| 执行型 | 创建单据、发起流程、催办、同步系统 | 幂等、审批点、回滚 |
| 编排型 | 多智能体协同处理复杂任务 | 步骤可控、日志回放、失败补偿 |

项目建议：先做问答型、生成型和分析型，再谨慎推进审核型和执行型。

## 五、财务场景

### 5.1 智能审核

适合：

- 费用报销附件和报销单一致性检查。
- 发票抬头、税号、金额、日期和报销事项校验。
- 重复报销、超预算、超标准、异常供应商识别。
- 付款申请与合同、发票、入库或验收资料勾稽。

落地清单：

| 检查项 | 说明 |
| --- | --- |
| 审核规则 | 哪些是硬规则，哪些是提示规则 |
| 附件解析 | 发票、回单、合同、截图是否可识别 |
| 主数据映射 | 员工、部门、供应商、费用项目 |
| 预算联动 | 是否检查预算余额、占用和释放 |
| 人工确认 | 超预算、疑似重复、金额异常必须人工确认 |
| 证据留存 | 保存识别结果、模型建议、人工处理结果 |

### 5.2 报告生成

适合：

- 月度经营分析报告草稿。
- 应收账龄和催收报告。
- 费用预算执行分析。
- 现金流预测说明。
- 合并报表差异说明。

报告生成不能直接替代财务结论。建议流程：

```text
标准报表/BI 数据
  -> AI 生成摘要和异常解释
  -> 财务人员复核口径和金额
  -> 管理层版本发布
```

### 5.3 财务指标问询

适合：

- “本月毛利率为什么下降？”
- “逾期应收主要集中在哪些客户？”
- “费用超预算来自哪些部门？”
- “本月收入和总账为什么有差异？”

要求：

- 必须显示指标公式、数据来源、期间、组织和权限范围。
- 敏感指标如利润、成本、价格、薪酬要单独授权。
- 重要结论必须能下钻到报表或单据。

## 六、供应链场景

### 6.1 采购助手

可做：

- 供应商准交率、价格波动、质量退货分析。
- 采购订单逾期提醒。
- 到货未开票和暂估金额提示。
- 采购申请推荐供应商或历史价格参考。

不能直接自动做：

- 未经授权自动下采购订单。
- 自动修改价格表。
- 自动更改供应商准入状态。

建议保留审批点：

| 动作 | 建议控制 |
| --- | --- |
| 推荐供应商 | AI 给建议，采购员确认 |
| 价格异常提示 | AI 提醒，采购负责人复核 |
| 生成采购订单草稿 | 可生成草稿，提交前人工确认 |
| 供应商冻结 | 必须走审批 |

### 6.2 库存和仓储助手

可做：

- 呆滞库存、临期批号、高金额库存提醒。
- WMS 回写失败和补偿建议。
- 盘点差异解释。
- 库存状态异常检查。

关键口径：

- 即时库存还是期间余额。
- 可用库存还是账面库存。
- 批号、库位、库存状态是否纳入。
- 是否和存货核算金额一致。

### 6.3 销售和售后助手

可做：

- 客户逾期应收提醒。
- 信用风险提示。
- 退货、RMA、索赔和备件状态查询。
- 服务站库存和经销商代修异常提示。

风险：

- 客户价格、折扣、毛利、信用额度属于敏感数据。
- 售后赔偿建议不能直接作为财务或法务承诺。
- 客户沟通内容需要人工确认。

## 七、制造场景

| 场景 | AI 可以做 | 必须人工确认 |
| --- | --- | --- |
| 生产异常分析 | 汇总延期订单、缺料、报工异常、质量异常 | 调整计划、承诺交期 |
| BOM 影响分析 | 汇总工程变更影响的采购、生产、库存和售后物料 | 生效日期、替代料策略 |
| MES 回写排查 | 分析失败批次、幂等键、工序映射、质量结果 | 数据补偿和重推 |
| 质量异常总结 | 汇总不良原因、批号、供应商、工序 | 判退、索赔和让步接收 |
| 制造成本解释 | 分析材料、人工、费用和异常成本 | 成本调整和关账 |

制造场景的原则：AI 适合帮你找异常和解释可能原因，不适合未经审批自动改计划、改 BOM、改成本或改质量结论。

## 八、开发和实施场景

### 8.1 实施顾问助手

可做：

- 根据调研记录生成蓝图草稿。
- 把用户问题匹配到模块、菜单、参数和流程。
- 生成 UAT 测试用例和培训提纲。
- 汇总上线问题和遗留风险。

### 8.2 开发助手

可做：

- 解释 BOS 插件结构、事件时机和风险。
- 根据需求生成伪代码或接口字段映射草稿。
- 辅助排查日志和报错。
- 生成回归测试清单。

注意：

- 生产插件代码必须由开发人员审查、编译、测试。
- AI 给出的字段标识、类名、接口参数要回到真实环境或官方文档核对。
- 不把 AI 生成的 SQL 直接用于生产修改。

## 九、企业知识库和 RAG

知识库问答是 AI 最容易落地的入口，但也最容易因为资料脏而失败。

### 9.1 适合进入知识库的资料

| 资料 | 例子 |
| --- | --- |
| 制度 | 报销制度、采购制度、权限制度 |
| 操作手册 | 月结手册、采购到付款、销售到收款 |
| 项目文档 | 蓝图、配置清单、接口文档、上线方案 |
| FAQ | 常见报错、处理步骤、联系人 |
| 培训材料 | 新人培训、岗位教程、案例复盘 |

### 9.2 不适合直接进入知识库的资料

- 未脱敏的客户隐私、员工薪酬、供应商底价。
- 已废弃版本的操作手册。
- 没有来源、没有日期、没有 owner 的临时聊天记录。
- 与当前产品版本不匹配的截图和菜单路径。
- 未审批的政策草案。

### 9.3 知识库质量检查

| 检查项 | 通过标准 |
| --- | --- |
| 来源 | 每个答案能显示引用来源 |
| 时效 | 资料有版本、日期和负责人 |
| 权限 | 用户只能检索自己有权看的文档 |
| 切分 | 长文档按标题、流程和问答合理切分 |
| 回答 | 不知道就提示无法确定，不编造 |
| 反馈 | 用户能标记答案有用或错误 |

## 十、智能体上线前的权限和安全

公开资料强调企业级权限管控、数据脱敏、身份管控、合规审计、风险监控、提示词注入攻击防范和有害输出过滤。项目里要把这些落实成检查项。

| 控制点 | 要求 |
| --- | --- |
| 身份认证 | 继承企业账号、组织、角色和数据权限 |
| 数据权限 | 问答、检索、工具调用都不能越权 |
| 字段脱敏 | 客户、供应商、价格、利润、薪酬等敏感字段可脱敏 |
| 工具权限 | 智能体只能调用授权工具 |
| 人工确认 | 创建、修改、审批、付款、下单等动作要有确认 |
| 操作审计 | 记录用户、问题、工具调用、返回结果和审批动作 |
| 注入防范 | 防止用户通过提示词绕过权限或让系统泄露配置 |
| 内容安全 | 阻断恶意、歧视、违法或泄密输出 |
| 私有数据 | 明确数据是否出域、是否可私有化部署 |

## 十一、AIGO 落地方法

金蝶公开资料提到 AIGO 方法论：Assessment & Architecture、Implementation、Governance、Operation。可以翻译成项目四步：

| 阶段 | 项目动作 | 交付物 |
| --- | --- | --- |
| A 分析与架构 | 选场景、评估数据、权限、流程和收益 | AI 场景评估表、架构草图 |
| I 实施与执行 | 建知识库、配技能、接工具、做试点 | 原型、测试记录、上线方案 |
| G 治理与管理 | 权限、脱敏、审计、指标、风险控制 | 治理规则、审计清单 |
| O 运营与优化 | 看使用率、准确率、节省时间、业务价值 | 运营报表、优化 backlog |

## 十二、场景评估表

每个 AI 场景上线前先填这个表。

| 字段 | 示例 |
| --- | --- |
| 场景名称 | 报销单智能审核 |
| 使用人 | 财务审核员、部门负责人 |
| 业务价值 | 减少附件核对时间，提前发现重复报销 |
| 输入 | 报销单、发票、附件、预算余额、制度 |
| 输出 | 审核建议、异常原因、证据链接 |
| 工具调用 | 查询员工、预算、发票、历史报销 |
| 权限 | 只能看本组织或授权范围 |
| 人工确认点 | 驳回、通过、付款前必须人工确认 |
| 风险 | 误判、漏判、越权、过期制度 |
| 验收 | 抽样准确率、误报率、漏报率、审计日志 |

## 十三、智能体验收清单

| 验收项 | 测试方法 | 通过标准 |
| --- | --- | --- |
| 身份权限 | 用不同角色账号测试相同问题 | 结果范围不同且符合权限 |
| 知识来源 | 问制度、流程、操作手册 | 答案带来源，不知道就说明无法确定 |
| 工具调用 | 查询单据、生成草稿、发起流程 | 工具调用有日志，有失败处理 |
| 人工确认 | 测试高风险动作 | 未确认前不能正式提交 |
| 数据脱敏 | 查询价格、利润、客户信息 | 非授权用户看不到敏感字段 |
| 注入防范 | 尝试让智能体忽略权限或泄露配置 | 被拒绝或转安全提示 |
| 准确率 | 抽样 50-100 个真实问题 | 达到项目约定准确率 |
| 可回放 | 查看一次完整处理链路 | 能看到问题、检索、工具、结果、人工动作 |
| 运营指标 | 上线后按周统计 | 有使用率、解决率、反馈和优化项 |

## 十四、常见失败模式

| 失败模式 | 表现 | 处理 |
| --- | --- | --- |
| 资料没治理 | 答案引用过期制度 | 建文档 owner 和失效日期 |
| 权限没继承 | 普通用户看到敏感数据 | 检查知识库、工具和数据权限 |
| 工具太危险 | 一句话直接修改业务单据 | 改成生成草稿和人工确认 |
| 只做演示 | 试点好看，上线没人用 | 绑定真实流程和 KPI |
| 没有审计 | 出错后不知道谁问了什么 | 强制日志、回放和导出记录 |
| 没有反馈 | 错误答案无人修正 | 建反馈入口和知识库维护流程 |
| 问题太泛 | “帮我管采购”无法执行 | 拆成具体场景和工具 |
| 只靠大模型 | 不接 ERP 数据和知识库 | 接 RAG、报表、接口和权限 |

## 十五、建议优先级

| 优先级 | 场景 | 原因 |
| --- | --- | --- |
| P0 | 知识问答、操作手册、FAQ、制度问答 | 风险低，价值快，适合普及 |
| P0 | ChatBI 问数和指标解释 | 管理价值高，但必须先做口径治理 |
| P1 | 报销附件识别和智能审核建议 | 可节省人工，但必须保留审核责任 |
| P1 | 采购价格、供应商和库存异常提醒 | 能形成管理动作，风险可控 |
| P1 | 项目实施助手和问题归类 | 提升顾问效率，便于知识沉淀 |
| P2 | 自动下单、自动审批、自动补偿 | 高风险，需要强流程和审计 |

税务平台、银企直连和接口批量补偿，是金蝶项目上线后最容易牵涉财务风险的三类集成。它们共同特点是：外部系统已经发生了真实业务，金蝶侧如果没有正确回写、补偿、对账和留痕，就会影响付款安全、发票申报、凭证、月结和审计。

可以先记住一句话：

```text
财务集成不能只看接口是否成功，要看业务事实、外部事实、金蝶单据、凭证和审计证据是否闭环。
```

## 二、三条事实线

财务集成排查不能只看接口日志。建议永远拆成三条事实线：

```text
业务事实：销售、采购、收款、付款、费用、退货、红冲
外部事实：税务平台、银行、发票服务商、电子档案、第三方平台
金蝶事实：业务单据、财务单据、凭证、总账、附件、接口日志
```

| 事实线 | 常见对象 | 关键问题 |
| --- | --- | --- |
| 业务事实 | 销售出库、采购入库、应收、应付、付款申请、费用报销 | 业务是否真实发生，是否已审核，是否需要开票或付款 |
| 外部事实 | 发票号码、税控状态、认证状态、银行流水、银行回单 | 外部是否已经成功，状态是否可追溯 |
| 金蝶事实 | 销售发票、采购发票、收付款单、凭证、接口日志 | 金蝶是否完整记录、生成凭证、参与对账和月结 |

上线验收时，不能只说“接口返回成功”。要能回答：

1. 外部平台是否真的成功。
2. 金蝶单据是否已更新正确状态。
3. 凭证和总账是否能反映这笔业务。
4. 附件、回单、发票和接口报文是否能查。
5. 失败后补偿是否会重复创建或重复付款。

## 三、税务平台和发票平台集成

### 3.1 常见链路

```text
销售 / 采购 / 费用业务
  -> 金蝶发票单据或发票申请
  -> 发票平台开具 / 采集 / 验真 / 认证
  -> 发票号码、状态、税额、红冲关系回写
  -> 应收应付、收入成本、税金科目和凭证
  -> 税务申报和电子档案
```

### 3.2 销项发票

| 环节 | 关注点 | 风险 |
| --- | --- | --- |
| 开票申请 | 来源销售订单、出库、应收或合同履约 | 开票口径和收入确认口径不一致 |
| 发票开具 | 发票号码、开票日期、税率、税额 | 发票已开但金蝶状态未回写 |
| 作废 / 红冲 | 原蓝票、红字信息、退货或折让 | 税务平台已红冲，金蝶应收未冲 |
| 回写金蝶 | 发票号码、状态、二维码、PDF 附件 | 回写失败导致后续对账缺证据 |
| 申报勾稽 | 销项税、未开票收入、已开票未收入 | 税务申报和总账税金科目不一致 |

### 3.3 进项发票

| 环节 | 关注点 | 风险 |
| --- | --- | --- |
| 发票采集 | 供应商、税号、发票号码、金额、税额 | 供应商主数据匹配错误 |
| 三单匹配 | 采购入库、采购发票、应付单 | 已认证但未形成应付或凭证 |
| 认证抵扣 | 勾选期间、抵扣状态、用途 | 认证期间和凭证期间不一致 |
| 进项转出 | 福利、非应税、损失、用途变化 | 税务调整没有凭证和附件 |
| 电子档案 | 发票影像、验真结果、认证记录 | 审计时找不到原始依据 |

### 3.4 必须保留的关键字段

| 字段 | 用途 |
| --- | --- |
| 外部平台单号 | 税务平台或发票服务商的唯一单号 |
| 发票号码 / 代码 | 发票事实的核心标识 |
| 蓝票 / 红票关系 | 追踪红冲、折让、退货 |
| 开票日期 | 决定税务期间 |
| 业务日期 / 入账期间 | 决定管理口径和总账期间 |
| 含税金额 / 不含税金额 / 税额 | 和应收应付、收入、税金科目勾稽 |
| 税率 | 判断税额差异 |
| 客户 / 供应商税号 | 防止主数据误匹配 |
| 回写状态 | 判断是否需要补偿 |
| 附件链接 | 电子发票、验真截图、红字信息表 |

## 四、银企回单和银行流水集成

### 4.1 常见付款链路

```text
付款申请
  -> 付款单
  -> 内部审批
  -> 银企提交
  -> 银行受理
  -> 银行成功 / 失败 / 退回
  -> 回单和流水回传
  -> 银行对账
  -> 付款凭证和总账
```

### 4.2 状态要分清

| 状态 | 含义 | 能不能算付款完成 |
| --- | --- | --- |
| 单据已审核 | 企业内部同意付款 | 不能 |
| 已提交银行 | 报文已发给银行 | 不能 |
| 银行已受理 | 银行收到并处理中 | 不能完全算 |
| 银行处理成功 | 银行已扣款或支付成功 | 通常可以 |
| 银行退回 / 失败 | 银行未完成付款 | 不能 |
| 回单已回传 | 有银行付款凭证 | 可作为附件证据 |
| 已银行对账 | 企业账和银行流水匹配 | 月结更稳 |

很多项目出问题，是因为把“提交成功”当成“支付成功”。银企状态字段、银行流水和回单附件必须一起看。

### 4.3 重复付款控制

| 控制点 | 说明 |
| --- | --- |
| 付款申请唯一性 | 同一合同、发票、应付单不要重复申请 |
| 收款账号校验 | 供应商名称、银行账号、开户行、联行号 |
| 金额和币别 | 大额、跨币别、零金额、负数要拦截 |
| 银企流水号 | 银行侧唯一流水必须回写 |
| 外部请求号 | 提交银行的请求号要可追踪 |
| 银行状态回查 | 超时后先查银行状态，再决定是否重推 |
| 审批和支付分离 | 制单、审核、支付、复核不能一人闭环 |

### 4.4 银行回单和银行对账

| 对象 | 要核对什么 |
| --- | --- |
| 付款单 | 金额、币别、收款方、付款账户、用途 |
| 银行流水 | 借贷方向、发生日期、银行交易流水号 |
| 银行回单 | 回单号、收付款账号、金额、电子签章 |
| 凭证 | 银行科目、往来科目、核算维度 |
| 对账结果 | 已勾对、未达账项、长时间未处理流水 |

## 五、接口批量补偿

### 5.1 先区分重试和补偿

| 类型 | 触发 | 目标 | 风险 |
| --- | --- | --- | --- |
| 自动重试 | 网络超时、临时失败、限流 | 尽快恢复成功 | 如果没有幂等会重复 |
| 人工补偿 | 业务校验失败、主数据缺失、状态不一致 | 修正问题后重推 | 操作人可能选错范围 |
| 批量补偿 | 大量历史失败、平台恢复、补丁后重跑 | 批量追平数据 | 影响面大，需要审批和抽样 |
| 反向补偿 | 金蝶成功但外部失败，或外部成功但金蝶失败 | 两边重新一致 | 容易误判主从 |

### 5.2 补偿前必须确认

补偿不是“再推一次”。补偿前至少确认：

1. 外部系统是否已经成功。
2. 金蝶是否已经生成单据。
3. 是否存在同业务单据、同外部单号、同金额的历史记录。
4. 当前错误是否可重试，还是主数据、权限、业务规则导致不可重试。
5. 补偿会创建新单、更新旧单、撤销旧单，还是只回写状态。
6. 是否需要业务、财务、接口负责人审批。

### 5.3 幂等键设计

建议不要只用一个外部单号。更稳的幂等键通常包含：

```text
业务类型 + 来源系统 + 外部单号 + 组织 + 单据方向 + 关键金额/行号
```

| 场景 | 建议幂等键 |
| --- | --- |
| 销售发票回写 | 发票平台 + 发票号码 + 购方税号 + 销方税号 |
| 红字发票 | 红票号码 + 原蓝票号码 + 红冲原因 |
| 采购发票采集 | 发票号码 + 供应商税号 + 不含税金额 + 税额 |
| 银企付款 | 付款单号 + 银行请求流水 + 付款账号 + 收款账号 |
| 银行流水导入 | 银行账号 + 银行交易流水号 + 交易日期 + 金额方向 |
| 费用附件识别 | 附件哈希 + 报销单号 + 发票号码 |

### 5.4 补偿执行流程

```text
冻结补偿范围
  -> 导出失败清单
  -> 分类错误原因
  -> 修复主数据/权限/配置/报文
  -> 小批量试补偿
  -> 抽样核对外部平台和金蝶结果
  -> 批量补偿
  -> 输出补偿报告
  -> 加入月结证据包
```

补偿报告至少包含：

| 字段 | 说明 |
| --- | --- |
| 补偿批次号 | 每次批量补偿唯一编号 |
| 补偿范围 | 时间、业务类型、组织、接口 |
| 原失败原因 | 主数据、权限、网络、业务校验、重复 |
| 处理方式 | 重推、回写状态、作废、红冲、人工修复 |
| 成功数量 / 失败数量 | 补偿结果 |
| 抽样结果 | 抽哪些单，怎么核对 |
| 审批人 | 谁批准补偿 |
| 操作人 | 谁执行补偿 |
| 后续事项 | 仍未处理的异常 |

## 六、对账口径

### 6.1 税务平台对账

| 对账对象 | 金蝶侧 | 外部侧 | 差异处理 |
| --- | --- | --- | --- |
| 销项发票 | 销售发票、应收、收入、销项税 | 税务平台蓝票、红票、作废 | 查状态回写、期间、红冲关系 |
| 进项发票 | 采购发票、应付、进项税 | 发票采集、认证抵扣 | 查供应商匹配、认证期间、凭证 |
| 未开票收入 | 收入确认、应收、合同履约 | 无发票或下期开票 | 做未开票收入台账 |
| 已开票未收入 | 销售发票、预收、合同负债 | 已开票 | 判断履约和收入确认 |
| 红字发票 | 红字应收应付、退货、折让 | 税务平台红票 | 查原蓝票和业务处理 |

### 6.2 银企回单对账

| 对账对象 | 金蝶侧 | 银行侧 | 差异处理 |
| --- | --- | --- | --- |
| 付款状态 | 付款单、付款申请、凭证 | 银行受理、成功、失败 | 不能用已提交替代已成功 |
| 银行流水 | 银行日记账、对账单 | 银行流水 | 查漏导、重复导、方向错误 |
| 银行回单 | 附件、电子档案 | 银行回单文件 | 查回单下载和归档 |
| 未达账项 | 企业已入账银行未入账，或反向 | 银行对账单 | 做未达账项清单 |
| 手工付款 | 手工录入付款单 | 银行真实流水 | 查是否绕过银企和审批 |

### 6.3 接口补偿对账

| 对账对象 | 口径 |
| --- | --- |
| 失败清单 | 所有未成功状态、可重试、不可重试、人工处理 |
| 成功清单 | 已生成单据、已更新状态、已生成凭证 |
| 重复风险 | 同外部单号、同发票号码、同银行流水号 |
| 异常关闭 | 人工关闭必须有原因和审批 |
| 月末未处理 | 阻塞月结、付款、申报和库存核算的异常必须升级 |

## 七、监控看板

财务集成建议做三个监控页。

### 7.1 今日接口状态

| 指标 | 用途 |
| --- | --- |
| 今日总请求数 | 判断接口是否正常运行 |
| 成功率 | 快速发现波动 |
| 失败数 | 进入失败队列 |
| 超时数 | 判断网络或外部平台问题 |
| 重试次数 | 判断是否存在循环重试 |
| 平均耗时 | 判断性能和外部响应 |

### 7.2 财务风险异常

| 异常 | 说明 |
| --- | --- |
| 税务平台已开票、金蝶未回写 | 影响申报和应收确认 |
| 金蝶已付款、银行未成功 | 付款状态不真实 |
| 银行已扣款、金蝶未付款 | 总账和银行不一致 |
| 发票已认证、采购发票未入账 | 进项税和应付不一致 |
| 同外部单号多张金蝶单据 | 可能重复入账 |
| 补偿失败超过 24 小时 | 需要人工升级 |

### 7.3 月结阻塞清单

月结前至少检查：

- 未回写发票状态。
- 税务平台和金蝶发票金额差异。
- 银企处理中付款。
- 银行成功但未生成付款单或凭证。
- 未归档回单和发票附件。
- 接口失败未补偿。
- 人工关闭但无审批记录的异常。

## 八、典型问题处理

### 8.1 发票平台已开票，金蝶没有发票号码

排查：

1. 固定开票申请号、发票号码、客户、金额和开票日期。
2. 查发票平台是否已开票成功。
3. 查金蝶接口日志：请求、响应、回写状态。
4. 查金蝶销售发票或应收单状态。
5. 判断是回写失败、字段映射错误、权限不足还是单据已关闭。

处理：

- 如果外部已成功，不能重复开票。
- 应优先回写状态和发票号码。
- 如需人工补录，必须保留发票平台截图、接口日志和审批记录。

### 8.2 银行已扣款，金蝶付款单仍是处理中

排查：

1. 查银行流水和回单。
2. 查银企请求流水和银行返回流水。
3. 查付款单状态和回写日志。
4. 查是否已有凭证和银行对账记录。

处理：

- 不要再次提交银行。
- 先回查银行状态，再补偿回写金蝶。
- 补传回单附件，并纳入银行对账。

### 8.3 批量补偿后出现重复单据

排查：

1. 按外部单号、发票号码、银行流水号查重复。
2. 查补偿批次和操作人。
3. 查是否缺少幂等键或补偿前未查询历史结果。
4. 判断重复单据是否已审核、已生成凭证、已参与月结。

处理：

- 先冻结继续补偿。
- 对未审核重复单据作废。
- 对已审核或已生成凭证的重复单据，按业务规则红冲、反审核或冲销。
- 修复幂等规则后再恢复补偿。

## 九、职责分工

| 角色 | 责任 |
| --- | --- |
| 财务负责人 | 定义税务、付款、对账和月结口径 |
| 出纳 / 资金 | 核对银行流水、回单、付款状态 |
| 税务会计 | 核对发票、认证、红冲、申报 |
| 接口顾问 | 负责字段映射、日志、幂等、补偿机制 |
| 开发人员 | 实现接口、补偿工具、监控和校验 |
| 运维人员 | 监控任务、队列、网络、证书、定时任务 |
| 审计 / 内控 | 复核权限、审批、补偿报告和证据包 |

## 十、上线验收清单

- [ ] 税务平台发票开具、采集、红冲、作废、认证状态能回写。
- [ ] 银企付款提交、受理、成功、失败、退回状态能区分。
- [ ] 银行回单和银行流水能归档和对账。
- [ ] 所有关键接口都有外部单号、请求号、响应号和日志。
- [ ] 幂等键覆盖发票号码、银行流水、外部单号等关键对象。
- [ ] 自动重试只处理可重试错误，不重试业务校验错误。
- [ ] 批量补偿有审批、批次号、范围、结果和抽样记录。
- [ ] 重复单据处理有红冲、作废、冲销和凭证处理流程。
- [ ] 月结前能导出未补偿、未回写、未对账清单。
- [ ] 接口账号权限最小化，敏感操作可审计。

这篇是 [国外财务与国际化核算专题](international-finance-accounting-guide.md) 的实操补充。总论页讲“国外财务要考虑什么”，本页讲“海外子公司真的要上线、月结和交集团报表包时，金蝶里要怎么拆对象、怎么建清单、怎么验收”。

使用边界：

- 不给具体国家税率、申报期限和法律结论。
- 税率、预提税、税收协定、发票合规和当地申报口径必须由当地财务、税务顾问或审计确认。
- 本页重点是金蝶项目可落地的系统对象、数据清单、月结节奏、报表包和排查方法。

一句话主线：

```text
先建清海外主体和本位币
再锁定当地法定账和集团报告账
再把税码、汇率、关联方、付款证据和报表包接上
最后用月结日历和差异表控制每个月交付
```

## 一、海外子公司上线前先问 20 个问题

不要一开始就问“科目怎么建”。国际化财务第一步是把边界问清楚。

| 问题 | 要拿到的答案 | 影响对象 |
| --- | --- | --- |
| 子公司在哪个国家或地区注册 | 国家、注册号、税号、法定名称、地址 | 组织、客户/供应商、发票、税务 |
| 子公司承担什么职能 | 销售公司、采购公司、制造基地、服务公司、控股公司 | 供应链流程、成本、转移定价 |
| 本位币是什么 | 当地法定本位币，是否和集团列报币不同 | 账簿、汇率、凭证、报表折算 |
| 常用交易币别有哪些 | 销售、采购、银行、集团往来使用的币别 | 单据币别、原币核算、调汇 |
| 当地适用什么会计准则 | 当地 GAAP、IFRS、US GAAP 或其他 | 会计政策、科目映射、调整分录 |
| 集团要求什么报告口径 | 中国准则、IFRS、集团管理口径 | 报表包、调整分录、合并抵消 |
| 是否需要多账簿 | 当地法定账、集团报告账、管理账 | 账簿、凭证模板、报表模板 |
| 当地主要税种是什么 | VAT、GST、Sales Tax、WHT、关税、地方税 | 税码、税率、税务台账 |
| 发票由谁开具 | 金蝶开票、外部税务平台、当地系统、人工票据 | 发票接口、附件归档、对账 |
| 银行付款怎么做 | 本地网银、银企接口、手工付款、集团资金池 | 付款单、银行账号、回单 |
| 是否存在外汇管制 | 购汇、结汇、跨境付款审批 | 付款审批、附件、资金计划 |
| 是否存在跨境服务费 | 管理服务费、特许权使用费、技术服务费 | 预提税、关联交易、应付 |
| 是否有集团内部交易 | 内部销售、内部采购、代采代销、资金拆借 | 内部客户供应商、抵消 |
| 是否有库存 | 本地仓、保税仓、第三方仓、寄售库存 | 库存组织、仓库、存货核算 |
| 是否有固定资产 | 办公资产、设备、租赁资产 | 固定资产卡片、折旧政策 |
| 是否有本地薪酬 | 员工费用、社保、个税、外包薪酬 | 费用、应付、凭证模板 |
| 是否已有当地系统 | 当地税务系统、WMS、银行、费用系统 | 接口、主数据映射、数据迁移 |
| 当地审计要求什么资料 | 发票、合同、银行回单、报关、税务申报 | 附件归档、证据包 |
| 集团报表包何时提交 | D+3、D+5、D+8 或其他 | 月结日历、责任人、关账节奏 |
| 谁负责最终确认 | 当地财务、集团财务、税务、审计、IT | 权限、审批、验收 |

项目上最常见的坑：实施顾问先建了组织、账簿和科目，月末才发现当地税务和集团报表包口径完全没问清。国际化财务宁愿前期多花时间问边界，也不要后期用补丁去救凭证和报表。

## 二、系统对象设计总图

海外子公司不是一个“组织”就能表达完整。建议拆成下面这些对象：

```text
法人主体
  -> 核算组织
  -> 账簿
  -> 本位币
  -> 会计政策
  -> 科目表和核算维度
  -> 税码和发票规则
  -> 客户供应商和关联方
  -> 银行账户和付款方式
  -> 库存组织和仓库
  -> 报表项目和集团映射
  -> 月结任务和证据包
```

### 2.1 主数据对象表

| 对象 | 最低要求 | 常见错误 |
| --- | --- | --- |
| 法人主体 | 法定名称、国家地区、注册号、税号、本位币 | 中文简称和当地法定名称混用 |
| 核算组织 | 和法人边界一致，明确启用期间 | 用业务组织代替财务核算组织 |
| 账簿 | 本位币、准则、期间、启用日期、会计政策 | 本位币选错，上线后无法轻松改 |
| 科目表 | 当地科目和集团科目映射关系 | 为了迎合集团报表，把当地法定科目做乱 |
| 核算维度 | 客户、供应商、部门、项目、产品线、关联方 | 用明细科目代替维度，后续分析僵硬 |
| 币别 | 本位币、交易币、集团列报币 | 只配置人民币和美元，忽略当地银行币别 |
| 汇率类型 | 记账汇率、期末调汇汇率、集团折算汇率 | 所有场景混用同一个汇率 |
| 税码 | 当地标准税、零税率、免税、进口税、预提税 | 把 VAT/GST/Sales Tax 全当中国增值税 |
| 客户供应商 | 国家、税号、币别、付款条件、关联方标识 | 集团内部公司没标关联方 |
| 银行账号 | 币别、账号、SWIFT/IBAN、本地清算信息 | 同一账号多币别混用，回单无法匹配 |
| 附件类型 | 合同、发票、报关、回单、完税凭证 | 只传发票，不留付款和税务证据 |
| 报表项目 | 当地报表、集团报表包、管理报表 | 报表项目没有映射，合并靠 Excel 手调 |

### 2.2 单账簿、多账簿和报表包怎么选

| 模式 | 适用情况 | 优点 | 风险 |
| --- | --- | --- | --- |
| 单一当地账簿 + 报表包转换 | 海外规模不大，集团只要月度报表包 | 系统简单，维护成本低 | 准则差异要靠调整分录和报表映射 |
| 当地账簿 + 集团报告账簿 | 准则差异明显，集团需要稳定合并口径 | 集团取数清晰，调整留痕好 | 凭证模板、科目映射、月结流程更复杂 |
| 当地系统 + 金蝶集团报表包 | 海外已有成熟本地系统 | 不强行替换本地系统 | 接口、口径和数据质量是关键 |
| 金蝶统一核算 | 海外主体较多，集团想统一管控 | 主数据和流程统一 | 当地税务、语言、银行、发票适配工作量大 |

判断建议：

1. 如果海外主体只是销售办事处或小型服务公司，先考虑“当地账簿 + 报表包转换”。
2. 如果存在美国、欧盟、东南亚等多地实体，且集团要求统一合并，至少要设计稳定的集团科目映射和报表包。
3. 如果当地税务发票和银行强依赖本地平台，不要硬把所有动作塞进金蝶，先设计接口和证据回传。
4. 如果集团要按区域、产品线、客户群做经营分析，维度设计要在上线前锁定，不能等报表阶段再补。

## 三、建账配置清单

### 3.1 组织和账簿

| 检查项 | 要求 | 验收方法 |
| --- | --- | --- |
| 法人主体 | 法定名称、国家、税号、币别完整 | 打印组织清单，让当地财务确认 |
| 核算组织 | 启用期间和业务开始日期一致 | 用第一笔业务单据验证生成凭证 |
| 账簿 | 本位币、会计政策、期间、启用日期正确 | 查看总账参数和期间控制 |
| 会计日历 | 当地财年和集团财年差异已确认 | 测试跨年期间和报表期间 |
| 多账簿关系 | 当地账和集团账映射清楚 | 抽样一笔业务看双口径结果 |

### 3.2 科目和维度

| 检查项 | 要求 | 验收方法 |
| --- | --- | --- |
| 当地科目表 | 满足当地报表、税务和审计 | 当地财务确认科目级次 |
| 集团科目映射 | 每个报表相关科目有集团映射 | 生成集团报表包试算 |
| 关联方维度 | 内部客户、供应商、公司间交易能识别 | 内部往来对账表能筛出来 |
| 区域维度 | 能按国家、区域、法人分析 | 抽取区域利润表 |
| 产品线维度 | 支持销售毛利和集团经营分析 | 销售出库到收入成本都带维度 |
| 项目维度 | 服务费、工程、研发、实施能归集 | 费用和收入可按项目查询 |

### 3.3 币别和汇率

| 检查项 | 要求 | 验收方法 |
| --- | --- | --- |
| 交易币别 | 销售、采购、银行常用币别完整 | 用订单、发票、收付款测试 |
| 本位币 | 每个账簿本位币明确 | 凭证本位币金额正确 |
| 集团列报币 | 报表包折算币别明确 | 报表包能输出集团币别 |
| 汇率来源 | 手工维护、接口同步或集团发布 | 查汇率维护记录和审批 |
| 汇率类型 | 交易汇率、期末重估、报表折算分开 | 抽样验证调汇和折算结果 |
| 期末调汇 | 应收、应付、银行、内部往来参与范围明确 | 调汇凭证可追溯 |

### 3.4 税码和发票

| 检查项 | 要求 | 验收方法 |
| --- | --- | --- |
| 国内标准税码 | 当地标准税率业务可识别 | 销售和采购发票税额正确 |
| 零税率/免税 | 出口、跨境服务、免税客户单独区分 | 税务台账能区分原因 |
| 进口税 | Import VAT/GST、关税、杂费处理清楚 | 进口采购案例能生成凭证 |
| 预提税 | 服务费、利息、特许权使用费可记录 | 付款凭证能体现税负和实际支付 |
| Sales Tax | 不和 VAT/GST 混用 | 美国销售案例不生成可抵扣进项逻辑 |
| 发票附件 | 发票、合同、税务文件可归档 | 从凭证反查附件 |

不要为了少建税码，把所有税务场景都塞到“其他税”。税码越粗，月末税务申报、审计抽样和跨境付款排查越痛苦。

### 3.5 银行和付款

| 检查项 | 要求 | 验收方法 |
| --- | --- | --- |
| 银行账号 | 账号、币别、开户行、SWIFT/IBAN 完整 | 付款单能正确带出账号 |
| 付款条件 | 客户和供应商付款周期明确 | 应收账龄和应付到期表正确 |
| 手续费 | 承担方、科目、币别清楚 | 银行回单金额和应收应付能核销 |
| 跨境审批 | 合同、发票、税务、外汇资料齐全 | 付款审批单附件完整 |
| 回单归档 | 回单和付款单、凭证关联 | 月结证据包可追溯 |

## 四、海外子公司月结日历

海外月结最怕“当地财务还没关账，集团已经催报表包”。建议把月结节奏拆成 D-5 到 D+8。

| 时间 | 动作 | 责任人 | 交付物 |
| --- | --- | --- | --- |
| D-5 | 检查未审核业务单据、未开票事项、未收付款事项 | 当地业务、当地财务 | 未完成事项清单 |
| D-4 | 核对银行流水、现金、票据、未达账 | 当地出纳 | 银行余额调节表 |
| D-3 | 核对应收、应付、预收、预付、内部往来 | 当地财务 | 往来对账表 |
| D-2 | 检查库存、在途、暂估、进口税费、成本差异 | 供应链财务 | 库存和成本检查表 |
| D-1 | 计提费用、薪酬、折旧、税金、预提税 | 当地财务 | 计提凭证清单 |
| D0 | 生成凭证、过账、关业务期间 | 当地财务 | 凭证生成报告 |
| D+1 | 期末调汇、汇兑损益检查 | 当地财务 | 外币重估清单 |
| D+2 | 输出当地试算平衡表、利润表、资产负债表 | 当地财务 | 当地报表 |
| D+3 | 准则调整、集团科目映射、报表包生成 | 集团财务 | 集团报表包 |
| D+4 | 内部往来和内部交易对账 | 双方财务 | 内部对账确认表 |
| D+5 | 报表包复核、异常解释、管理摘要 | 集团财务 | 报表包和异常说明 |
| D+6 至 D+8 | 合并抵消、集团报表、审计资料归档 | 集团财务、审计 | 合并底稿和证据包 |

### 4.1 每月固定检查口径

| 检查项 | 看什么 | 异常信号 |
| --- | --- | --- |
| 未审核单据 | 销售、采购、库存、收付款、费用 | 单据已发生但没有入账 |
| 凭证失败 | 业务单据到总账凭证 | 科目、维度、税码、币别缺失 |
| 外币余额 | 应收、应付、银行、内部往来 | 原币余额正常，本位币异常 |
| 调汇范围 | 哪些科目参与期末重估 | 银行或往来没有调汇 |
| 税务台账 | 销项、进项、进口税、预提税 | 税额和发票/付款不一致 |
| 关联交易 | 内部销售、采购、服务费、资金拆借 | 对方公司不确认或金额不同 |
| 报表映射 | 科目到集团报表项目 | 当地报表平，集团报表不平 |
| 附件归档 | 发票、合同、回单、报关、完税凭证 | 审计抽样找不到证据 |

## 五、集团报表包设计

报表包不要只是一张 Excel。它应该是一套可复核的集团上报材料。

### 5.1 报表包最小内容

| 内容 | 说明 |
| --- | --- |
| 子公司基本信息 | 公司代码、国家、本位币、报表期间、关账日期 |
| 当地试算平衡表 | 当地科目、本位币金额、原币明细 |
| 集团科目映射表 | 当地科目到集团科目、报表项目的映射 |
| 准则调整表 | 当地准则到集团口径的调整分录 |
| 外币折算表 | 本位币到集团列报币的汇率和折算金额 |
| 内部往来表 | 内部客户、供应商、余额、差异、确认人 |
| 内部交易表 | 内部收入、成本、服务费、利息、特许权使用费 |
| 税务摘要 | VAT/GST/Sales Tax、WHT、进口税、当期申报状态 |
| 现金银行表 | 银行余额、未达账、受限资金、资金预测 |
| 异常说明 | 大额波动、一次性事项、未解决差异、责任人 |

### 5.2 报表包字段建议

| 字段 | 用途 |
| --- | --- |
| CompanyCode | 子公司编码 |
| CountryRegion | 国家或地区 |
| LocalCurrency | 本位币 |
| GroupCurrency | 集团列报币 |
| Period | 会计期间 |
| LocalAccount | 当地科目 |
| LocalAccountName | 当地科目名称 |
| GroupAccount | 集团科目 |
| ReportLine | 报表项目 |
| OriginalCurrency | 原币 |
| OriginalAmount | 原币金额 |
| LocalAmount | 本位币金额 |
| ExchangeRate | 折算汇率 |
| GroupAmount | 集团币金额 |
| AdjustmentType | 准则调整、重分类、抵消前调整 |
| RelatedParty | 是否关联方 |
| IntercompanyPartner | 内部交易对方公司 |
| EvidenceLink | 附件或证据包链接 |

### 5.3 报表包复核规则

| 规则 | 说明 |
| --- | --- |
| 试算平衡 | 借贷余额必须平 |
| 当地报表一致 | 报表包应能追溯到当地总账 |
| 集团映射完整 | 所有有效科目必须有集团科目和报表项目 |
| 调整分录留痕 | 每笔准则调整要有原因、附件和审批 |
| 折算汇率可追溯 | 汇率来源、日期、类型明确 |
| 内部交易可匹配 | 双方公司、币别、金额、差异原因明确 |
| 税务状态可说明 | 税务申报、预提税和完税资料有状态 |
| 异常事项有人负责 | 金额、原因、影响、责任人、关闭日期明确 |

## 六、典型业务场景怎么测

### 6.1 外币销售到收款

测试步骤：

1. 海外子公司用交易币别开销售订单。
2. 销售出库或服务确认。
3. 生成应收单和发票。
4. 用外币收款，银行扣手续费。
5. 月末做外币重估。
6. 输出客户账龄和总账余额。

验收点：

- 原币金额、本位币金额、税额、汇率都正确。
- 银行手续费不冲掉客户应收。
- 客户账龄按原币和本位币都能解释。
- 调汇后汇兑损益能追溯到应收科目。

### 6.2 进口采购到付款

测试步骤：

1. 用外币采购订单下单。
2. 到货入库，形成暂估。
3. 收到供应商发票。
4. 录入进口税、关税、物流费或清关费。
5. 付款并归档银行回单。
6. 月末核对存货成本和应付余额。

验收点：

- 进口税费是否进入正确科目或成本。
- 暂估和发票差异是否有处理路径。
- 应付原币余额和本位币余额能对上。
- 报关单、发票、付款回单能从单据或凭证追溯。

### 6.3 跨境服务费和预提税

测试步骤：

1. 建立服务合同和供应商。
2. 录入服务费应付。
3. 根据当地确认的税务口径记录预提税。
4. 付款时区分合同金额、预提税、实际支付金额和手续费。
5. 取得完税凭证并归档。

验收点：

- 应付金额、预提税负债、银行支付金额能解释。
- 完税凭证和付款记录能关联。
- 关联服务费纳入关联交易台账。
- 集团报表包能识别该笔跨境服务费。

### 6.4 内部销售和合并抵消

测试步骤：

1. 母公司向海外子公司销售。
2. 一方形成销售收入和应收，另一方形成采购和应付。
3. 双方使用可能不同的币别和汇率。
4. 月末双方确认内部往来余额。
5. 集团生成内部交易抵消底稿。

验收点：

- 内部客户、内部供应商和对方公司标识一致。
- 双方原币金额和本位币金额差异能解释。
- 内部收入、内部成本和内部往来可以被报表包识别。
- 未实现内部利润有清单和调整入口。

## 七、月结差异排查表

| 现象 | 优先查什么 | 常见处理 |
| --- | --- | --- |
| 当地试算表平，集团报表包不平 | 科目映射、报表项目、调整分录方向 | 补映射，重跑报表包 |
| 原币余额对，本位币余额不对 | 汇率、调汇范围、历史凭证汇率 | 复核汇率类型和调汇凭证 |
| 银行余额和总账不一致 | 未达账、手续费、跨币别付款 | 做银行余额调节表 |
| 应收账龄和总账不一致 | 核销状态、原币本位币、客户维度 | 按客户和币别重对账龄 |
| 应付付款后仍有余额 | 预提税、手续费、短付、汇差 | 拆分付款差额原因 |
| VAT/GST 台账和总账不一致 | 发票状态、税码、凭证模板 | 按税码和发票类型重对 |
| 预提税漏记 | 付款类型未分类、供应商税务属性缺失 | 补供应商税务属性和付款检查 |
| 内部往来双方不一致 | 对方公司、期间、币别、单据状态 | 做双方确认表 |
| 报表折算差异异常 | 折算汇率、报表项目属性、历史汇率 | 核对折算规则 |
| 审计抽样找不到资料 | 附件类型缺失、归档责任不清 | 建证据包清单和附件规则 |

## 八、角色分工

| 角色 | 负责什么 | 不该只靠谁 |
| --- | --- | --- |
| 当地财务 | 当地科目、税务、发票、银行、审计资料 | 不能只靠集团财务猜当地口径 |
| 集团财务 | 集团科目、报表包、合并、内部往来 | 不能只看报表不管源单据 |
| 税务顾问 | 税率、预提税、税收协定、申报规则 | 不能让实施顾问给税务结论 |
| 实施顾问 | 组织、账簿、科目、税码、流程、报表落地 | 不能绕过财务确认直接配置 |
| 开发/集成 | 银行、税务平台、本地系统接口 | 不能只做接口成功，不做业务对账 |
| 审计/内控 | 附件、审批、证据、职责分离 | 不能等上线后才要求补证据 |

出纳与资金不只是“录收付款单”。企业规模一大，就会出现银企直连、付款审批、银行回单、银行对账、应收票据、应付票据、票据背书贴现、资金计划、资金预测等场景。

这些内容如果只靠出纳个人经验，很容易出问题：付款已经在银行扣款，金蝶状态没回写；银行流水重复导入；票据背书后应收还挂着；资金计划和实际付款对不上；付款审批通过但银行退回。

这篇专题把银企、票据和资金计划串在一起，重点讲流程、控制点和排查。

## 一、资金业务大图

```text
付款申请 / 收款计划 / 票据到期
  -> 资金计划和额度判断
  -> 收款单、付款单、票据单据
  -> 审批
  -> 银企直连提交银行
  -> 银行处理结果回写
  -> 银行回单 / 银行对账单
  -> 银行对账
  -> 凭证和总账对账
```

资金模块的目标不是“单据录进去”，而是：

- 钱有没有真实收付。
- 谁批准了收付。
- 银行处理状态是否回写。
- 银行流水和企业账是否对上。
- 票据是否到期、背书、贴现或托收。
- 未来现金流是否可预测。

## 二、关键对象

| 对象 | 作用 | 常见风险 |
| --- | --- | --- |
| 银行账号 | 企业资金账户 | 账号、开户行、币别、科目映射错误 |
| 收款单 | 记录客户或其他收款 | 未核销导致应收账龄不变 |
| 付款申请单 | 付款的前置申请 | 申请和实际付款脱节 |
| 付款单 | 记录供应商或其他付款 | 审批通过但银行付款失败 |
| 银企直连 / 网上银行 | 系统和银行交互 | 提交成功不等于银行支付成功 |
| 银行对账单 | 银行侧流水 | 重复导入、漏导、金额方向错误 |
| 应收票据 | 客户用票据付款 | 到期托收、背书、贴现状态不清 |
| 应付票据 | 企业开出票据付款 | 到期兑付、保证金、承兑责任 |
| 资金计划 | 预测未来收支 | 计划口径和实际单据口径不一致 |
| 资金凭证 | 进入总账 | 未生成、未过账、银行科目映射错误 |

## 三、银企直连流程

```text
付款申请
  -> 付款单
  -> 内部审批
  -> 银企提交
  -> 银行受理
  -> 银行成功 / 失败 / 退回
  -> 回单或流水回传
  -> 银行对账
  -> 生成凭证
```

要特别区分几个状态：

| 状态 | 含义 | 能不能算付款完成 |
| --- | --- | --- |
| 单据已审核 | 企业内部同意付款 | 不能 |
| 已提交银行 | 已发给银行 | 不能 |
| 银行已受理 | 银行收到并处理中 | 不能完全算 |
| 银行支付成功 | 银行已经扣款 | 可以作为付款完成依据 |
| 银行失败 / 退回 | 银行未执行 | 不能，需要重提或作废 |
| 银行流水已回传 | 银行侧有扣款记录 | 可用于对账和回单归档 |

很多争议来自一句话：“系统显示成功了”。要问清楚是哪种成功：金蝶提交成功，银行受理成功，还是银行扣款成功。

## 四、银企直连控制点

| 控制点 | 检查内容 |
| --- | --- |
| 银行账号 | 账号、户名、开户行、币别、用途、科目映射 |
| 收款方资料 | 供应商户名、账号、开户行是否和银行要求一致 |
| 付款审批 | 金额、部门、项目、供应商、预算是否审批 |
| 银行权限 | 制单、复核、授权、UKey 或银行授权角色分离 |
| 提交结果 | 金蝶提交是否成功，银行是否受理 |
| 回单流水 | 是否能回传银行回单或银行对账单 |
| 失败处理 | 失败单据是否允许重提，是否避免重复付款 |
| 对账 | 企业账和银行账是否匹配 |

建议把“银行支付成功回写”作为付款闭环节点。只靠付款单审核，会把银行退回、余额不足、账号错误等问题盖住。

## 五、银行对账和回单

银行对账是资金可信的核心。

```text
企业账：收款单 / 付款单 / 银行转账单 / 银行日记账
银行账：银行对账单 / 银企流水 / 银行回单
  -> 自动匹配
  -> 手工匹配
  -> 未达账项说明
  -> 月末余额核对
```

常见未达账：

| 类型 | 说明 | 处理 |
| --- | --- | --- |
| 银行已付，企业未付 | 银行扣款了，金蝶付款单没有或失败 | 补录或修复银企回写 |
| 企业已付，银行未付 | 金蝶付款单审核了，但银行未扣款 | 查银行状态，不要急着生成付款完成结论 |
| 银行已收，企业未收 | 客户已打款，收款单未录 | 补录收款单并核销 |
| 企业已收，银行未收 | 金蝶先录了收款，银行暂未到账 | 跟踪到账或冲回 |
| 手续费差异 | 银行扣了手续费 | 补费用单或手续费分录 |
| 重复流水 | 银行对账单重复导入 | 删除重复导入或做导入去重规则 |

## 六、应收票据

应收票据是客户用票据抵付货款或债务。常见类型包括银行承兑汇票、商业承兑汇票等。

```text
客户开出票据
  -> 企业收到应收票据
  -> 票据登记
  -> 和应收款核销
  -> 持有到期托收 / 背书转让 / 贴现
  -> 到期收款或票据风险处理
```

关键动作：

| 动作 | 含义 | 财务影响 |
| --- | --- | --- |
| 收票 | 客户用票据支付 | 应收账款减少，应收票据增加 |
| 背书 | 将票据转给供应商 | 应收票据减少，应付账款减少 |
| 贴现 | 提前向银行取得现金 | 银行存款增加，可能产生贴现利息 |
| 托收 | 到期向银行收款 | 银行存款增加，应收票据减少 |
| 退票 / 拒付 | 到期未能收款 | 恢复应收或进入风险处理 |

常见分录方向：

```text
收到客户票据：
借：应收票据
  贷：应收账款-客户

票据到期托收：
借：银行存款
  贷：应收票据

票据贴现：
借：银行存款
借：财务费用-贴现息
  贷：应收票据
```

## 七、应付票据

应付票据是企业用票据支付供应商或其他债务。

```text
付款申请 / 应付到期
  -> 开具应付票据
  -> 交付供应商
  -> 和应付款核销
  -> 到期承兑付款
  -> 银行扣款和凭证
```

关键检查：

- 是否有真实采购或付款依据。
- 票据金额、到期日、收款方是否正确。
- 是否需要保证金。
- 到期是否自动或手工兑付。
- 到期付款是否和银行流水对上。
- 应付票据余额是否有到期清单。

常见分录方向：

```text
开出应付票据：
借：应付账款-供应商
  贷：应付票据

到期兑付：
借：应付票据
  贷：银行存款
```

## 八、资金计划

资金计划不是会计凭证，而是管理预测。它关心未来某段时间预计收多少钱、付多少钱、缺不缺钱。

```text
销售订单 / 应收账龄 / 收款计划
采购订单 / 应付账龄 / 付款计划
费用预算 / 工资税费 / 投资融资
  -> 资金计划
  -> 资金缺口或富余
  -> 付款排程
  -> 实际收付回写
  -> 滚动预测
```

资金计划常见来源：

| 来源 | 收入 / 支出 | 说明 |
| --- | --- | --- |
| 应收账龄 | 预计收款 | 按客户到期日和承诺付款日预测 |
| 销售订单 | 未来收款 | 适合预收或项目回款 |
| 应付账龄 | 预计付款 | 按供应商付款条件预测 |
| 采购订单 | 未来付款 | 大额采购提前纳入计划 |
| 费用报销 | 费用支出 | 报销审批后形成短期付款需求 |
| 工资社保税费 | 固定支出 | 按月份计划 |
| 借款还款 | 融资现金流 | 本金、利息、手续费 |

## 九、资金计划和实际差异

| 差异现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 计划有付款，实际没付 | 审批未过、银行失败、供应商资料错误 | 查付款状态和银行回写 |
| 实际付款超过计划 | 临时付款、计划未及时更新 | 建立超计划审批 |
| 计划收款未到账 | 客户逾期、发票争议、质量争议 | 联动应收催收 |
| 实际到账没有计划 | 预收款、客户提前付款、计划漏录 | 补充计划来源 |
| 资金缺口预测不准 | 应收承诺日期不准、应付排程不准 | 周滚动更新 |

资金计划要和应收账龄、应付账龄、付款申请、银企支付联动，否则计划只是表格，不能指导付款安排。

## 十、常见案例

### 案例 1：付款单已审核，但供应商说没收到钱

排查：

1. 付款单是否只是内部审核完成。
2. 是否提交银企。
3. 银行是否受理。
4. 银行是否支付成功。
5. 是否有银行回单或流水。
6. 收款方户名、账号、开户行是否错误。

处理：

- 如果银行失败，按失败原因修正后重提。
- 如果银行成功，提供回单给供应商。
- 如果付款单已生成凭证但银行失败，要冲回或撤销付款结果。

### 案例 2：银行流水重复导入，银行余额对不上

排查：

1. 同一银行账号、同一日期、同一流水号是否重复。
2. 对账单导入批次是否重复。
3. 银企接口是否同时手工导入。
4. 银行流水唯一标识是否维护。

处理：

- 删除或标记重复流水。
- 固化导入去重规则。
- 月末保存导入批次和银行原始文件。

### 案例 3：客户给了票据，但应收账龄仍逾期

排查：

1. 应收票据是否登记。
2. 应收票据是否和原应收核销。
3. 票据客户和应收客户是否一致。
4. 票据是否被背书、贴现或退票。

处理：

- 做应收票据与应收款核销。
- 如果票据退票，要恢复客户应收并进入催收。
- 对商业承兑票据单独做风险跟踪。

### 案例 4：资金计划显示够钱，实际付款时余额不足

排查：

1. 资金计划是否包含已审批未付款单。
2. 是否有冻结资金、保证金、票据保证金。
3. 是否有当天临时付款未纳入计划。
4. 是否按银行账号分别预测，而不是只看总余额。

处理：

- 资金计划按账号、币别、日期细分。
- 对大额临时付款设置超计划审批。
- 每周滚动更新未来 4-8 周资金计划。

## 十一、月末检查清单

- [ ] 付款申请、付款单、收款单全部审核或有说明。
- [ ] 银企提交失败、银行退回、处理中单据已清理。
- [ ] 银行对账单导入完整且无重复。
- [ ] 银行对账完成，未达账项有说明。
- [ ] 银行回单和大额付款附件已归档。
- [ ] 应收票据余额有到期清单。
- [ ] 应付票据余额有到期清单。
- [ ] 票据背书、贴现、托收状态和凭证一致。
- [ ] 资金计划和实际收付差异已复盘。
- [ ] 现金银行科目与出纳账、银行流水一致。
- [ ] 银行账号、付款权限和审批权限符合职责分离。

## 十二、学习练习

建议在测试环境做 4 组练习：

1. 做一笔付款申请、付款单、银企提交、银行回写、银行对账。
2. 做一笔客户应收票据收票、核销、到期托收。
3. 做一笔应付票据开票、交付供应商、到期兑付。
4. 做一张未来 4 周资金计划，比较计划收付和实际收付差异。

学会的标准：

- 能区分“付款单审核成功”和“银行支付成功”。
- 能解释银行未达账项的四种基本类型。
- 能把票据状态和应收应付余额对起来。
- 能从资金计划追到应收账龄、应付账龄和付款排程。

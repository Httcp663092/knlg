这篇用于补齐“生产订单已经下达，但现场到底做到哪一步、MES 回写是否可信、设备采集数据能否进成本和质量追溯”的场景。它不是单纯讲 MES 概念，而是把金蝶生产订单、车间报工、设备采集、质量检验、完工入库、库存耗用、制造成本和看板指标串起来。

现场系统越多，越要先划清边界。金蝶通常承担计划、订单、库存、成本、财务和主数据闭环；MES 更贴近车间任务、工位执行、采集、异常和追溯；设备、PLC、IoT 网关、条码终端只是数据来源，不能替代业务规则。

## 一、适用范围

- 生产订单下达到车间后，需要按工序、班组、产线、设备跟踪进度。
- 车间用 MES、条码终端、扫码枪、电子看板、设备网关或 PLC 采集生产数据。
- MES 需要把报工、完工、用料、检验、不良、停机等结果回写到金蝶。
- 管理层需要看订单进度、产能负荷、在制品、瓶颈、良率和停机异常。
- 成本会计需要确认报工工时、材料倒冲、完工数量和制造费用分摊是否可信。

不适合一开始就做得太重的情况：

- 企业只有简单离散生产，只需要生产订单领料和完工入库。
- 现场没有稳定工艺路线、工作中心、人员设备编码，先上 MES 反而会放大混乱。
- 设备数据采集只是展示，不参与报工、质量、成本和追溯，可先作为看板二期。

## 二、完整业务链路

```text
销售预测或销售订单
  -> MRP 运算
  -> 生产订单
  -> 工艺路线和工序计划
  -> 派工或 MES 工单
  -> 工位扫码开工
  -> 设备数据采集
  -> 工序报工
  -> 质量检验
  -> 材料耗用或倒冲
  -> 在制品和工序进度
  -> 完工入库
  -> 存货核算
  -> 制造成本计算
  -> 凭证和管理报表
```

这个链路里最容易出问题的是“中间状态”。金蝶里生产订单还没完工，MES 里显示已完成；MES 里设备已经跑出产量，金蝶报工单没生成；金蝶完工入库已经审核，质量检验和材料倒冲还没有闭环。上线前必须把每个状态的来源、负责人和修复办法定清楚。

## 三、系统边界

| 系统或工具 | 主要职责 | 不建议承担的职责 |
| --- | --- | --- |
| 金蝶 | 生产订单、BOM、工艺路线、库存、成本、财务、主数据、单据状态 | 直接采集 PLC 秒级数据、替代现场设备控制 |
| MES | 车间任务、派工、工位执行、报工、不良、返工、追溯、现场看板 | 自行决定财务成本、绕过金蝶库存和订单状态 |
| WMS | 原材料、半成品、成品的仓储执行、批号库位、上下架、出入库扫码 | 决定生产进度和工序质量 |
| 设备/PLC | 运行状态、产量计数、节拍、报警、停机、能耗、测试结果 | 判断订单是否可完工、是否可入库 |
| IoT 网关 | 采集、清洗、缓存、协议转换、断点续传 | 替代 MES 或金蝶业务单据 |
| 条码终端 | 扫描工单、人员、设备、物料、批号并触发现场动作 | 保存唯一业务事实而不回写系统 |
| BI/看板 | 展示订单、产能、良率、异常和趋势 | 作为唯一数据源修改业务状态 |

边界判断原则：

- 谁产生业务事实，谁保存原始记录。
- 谁负责财务和库存影响，谁生成正式单据。
- 谁最靠近现场，谁保存采集明细。
- 跨系统必须有外部单号、幂等键、处理状态和对账报表。

## 四、主数据映射

MES 和金蝶集成失败，很多不是接口技术问题，而是主数据没有对齐。

| 主数据 | 金蝶关注点 | MES/现场关注点 | 常见坑 |
| --- | --- | --- | --- |
| 物料 | 编码、规格、计量单位、批号策略、库存属性 | 工位显示名称、扫码规则、替代料 | MES 使用旧料号或客户料号，回写时找不到物料 |
| BOM | 版本、生效日期、用量、损耗、替代料 | 工位用料清单、投料顺序、关键件追溯 | 现场按临时变更生产，金蝶 BOM 未同步 |
| 工艺路线 | 工序顺序、工作中心、标准工时、关键工序 | 工位、产线、设备、作业指导书 | MES 工序拆得更细，回写不到金蝶工序 |
| 工作中心 | 产线、班组、能力、成本中心 | 工段、工位、设备组 | 工作中心粒度太粗，看板无法解释瓶颈 |
| 设备 | 设备编码、维护台账、产能 | PLC 点位、状态、报警、节拍 | 设备编码和资产编码不一致 |
| 人员 | 操作员、班组、权限、岗位 | 扫码登录、班次、绩效 | 代扫、共用账号导致追溯失真 |
| 批号/序列号 | 库存追溯、出入库控制 | 投料、产出、检验、返修追溯 | 只在 MES 有序列号，金蝶无法查到来源 |
| 仓库/库位 | 领料、退料、完工入库、在制仓 | 线边仓、工位料架、不良品区 | 线边库存没有在金蝶形成可对账仓位 |
| 不良代码 | 质量统计、责任分析、返修报废 | 现场异常录入、检验项 | 代码体系不统一，良率统计无法合并 |
| 停机代码 | 设备效率、异常追踪 | 设备报警、人工停机原因 | 设备自动停机和人工原因没有归类 |

上线前要输出一张《MES 与金蝶主数据映射表》，至少包含编码、名称、来源系统、同步方向、是否必填、是否允许手工新增、变更审批人和异常处理方式。

## 五、数据采集类型

| 采集类型 | 典型数据 | 适合用途 | 风险控制 |
| --- | --- | --- | --- |
| 人工报工 | 开工、完工、合格数、不良数、工时 | 管理简单、设备不联网的工序 | 必须限制超报、漏报和跨工序报工 |
| 条码扫码 | 工单、工序、人员、设备、物料、批号 | 工位追溯、投料防错、序列号管理 | 条码规则、重扫处理、离线缓存要明确 |
| 设备自动计数 | 产量、节拍、运行状态 | 自动化产线、连续生产 | 设备计数不等于合格数量，要经过业务确认 |
| PLC/IoT 数据 | 状态、报警、温度、压力、能耗 | 设备监控、质量追溯、看板 | 点位含义、采样频率、异常值过滤要记录 |
| 称重采集 | 投料重量、产出重量、损耗 | 化工、食品、冶金等行业 | 皮重、单位换算、称重设备校准要留痕 |
| 测试结果 | 合格/不合格、参数值、曲线、文件 | 质量追溯、出厂检测 | 测试结果要能关联批号或序列号 |
| 质量检验 | 抽检、全检、不良原因、处置方式 | 入库前判定、返修、让步接收 | 检验结论必须影响报工或入库策略 |
| 能耗采集 | 电、水、气、蒸汽 | 成本分摊、节能分析 | 不要直接把秒级数据塞进业务单据 |

采集设计不要追求“什么都实时”。能影响订单进度、质量判定、库存耗用、成本核算的数据要优先稳定；只用于大屏展示的数据可以先缓冲、汇总后再分析。

## 六、MES 回写金蝶的单据和状态

| 回写内容 | 触发时点 | 金蝶侧结果 | 对账重点 |
| --- | --- | --- | --- |
| 开工状态 | 工位扫码开工 | 工序任务或生产订单进度更新 | 是否允许重复开工、跨班次开工 |
| 工序报工 | 工序完成或批次完成 | 报工单、工序进度、工时记录 | 合格数、不良数、返工数、工时 |
| 材料耗用 | 投料扫码或报工倒冲 | 生产领料、补料、退料、倒冲记录 | 是否负库存、是否批号正确 |
| 质量结果 | 报工后检验或设备测试后 | 检验单、不良记录、返修/报废状态 | 检验结论是否影响完工入库 |
| 完工入库 | 最后工序合格完成 | 完工入库单、库存增加 | 入库仓库、批号、数量、日期 |
| 返工返修 | 不良判定后 | 返工任务、补充报工或返修记录 | 是否重复计算产量和工时 |
| 停机异常 | 设备停机或人工上报 | 异常记录、设备状态、看板告警 | 停机原因、开始结束时间、责任分类 |

回写必须具备：

- 外部系统单号，例如 MES 工单号、报工流水号、设备采集批次号。
- 金蝶源单信息，例如生产订单号、分录号、工序号、物料、组织。
- 幂等键，例如 `组织 + 生产订单 + 工序 + 报工流水号`。
- 回写状态，例如待发送、发送中、成功、失败、已人工处理。
- 错误原文和重试次数。
- 人工补偿入口和补偿记录。

## 七、看板指标设计

看板不是把所有字段放到大屏，而是把“现场是否按计划运行”说清楚。

| 指标 | 口径 | 注意点 |
| --- | --- | --- |
| 订单进度 | 已报工合格数 / 订单计划数 | 要区分工序进度和完工入库进度 |
| 工序在制 | 已开工未完工数量 | 需要处理跨班次、返工、暂停 |
| 工作中心负荷 | 已排任务工时 / 可用工时 | 工作中心粒度必须和排产粒度一致 |
| 设备开动率 | 运行时间 / 计划开机时间 | 停机代码要分类，不能只看设备信号 |
| 性能效率 | 实际节拍与标准节拍对比 | 标准节拍过旧会让指标失真 |
| 质量良率 | 合格数 / 投入或产出数量 | 要明确返工后合格是否重复计入 |
| 瓶颈工序 | 队列最长、延期最多或负荷最高的工序 | 不能只看单点产能，要看上下游节拍 |
| 材料齐套率 | 已备齐物料 / 需求物料 | 要考虑替代料、线边库存和待检库存 |
| 异常闭环率 | 已关闭异常 / 异常总数 | 要记录责任人、原因和处理时长 |
| 报工回写成功率 | 成功回写笔数 / 应回写笔数 | 要按接口批次和业务日期双口径统计 |

看板建议分三层：

1. 车间现场层：当前任务、设备状态、缺料、不良、停机、待处理异常。
2. 生产管理层：订单达成、工序瓶颈、产线负荷、良率、返修、延期。
3. 经营管理层：产能趋势、成本异常、制造效率、交付风险、质量损失。

## 八、集成设计要点

### 接口方向

| 方向 | 数据 |
| --- | --- |
| 金蝶 -> MES | 物料、BOM、工艺路线、工作中心、生产订单、用料清单、仓库、批号规则 |
| MES -> 金蝶 | 报工、工时、合格数、不良数、投料耗用、完工入库、检验结果、异常记录 |
| 设备 -> MES/网关 | 计数、状态、报警、参数、能耗、测试结果 |
| 金蝶 -> 看板/BI | 订单、库存、成本、财务和主数据口径 |

### 幂等和重试

- 业务单据回写必须先查是否已成功生成下游单据，再决定新增还是补偿。
- 设备采集明细可以高频写入采集库，业务汇总后再生成报工。
- 接口超时不能简单重发新增请求，要用幂等键查询结果。
- 失败记录要按“主数据不存在、状态不允许、数量异常、权限不足、系统异常”分类。
- 人工处理后要保留原始失败报文、处理人、处理时间和补偿单号。

### 时间和班次

- 报工日期、业务日期、实际采集时间、接口发送时间、金蝶创建时间必须分清。
- 夜班跨天要明确属于哪个生产日期和成本期间。
- 设备秒级数据不要直接决定财务期间，财务影响以正式单据日期和期间为准。

### 权限和审计

- MES 接口账号不能直接拥有所有组织和所有单据权限。
- 关键回写动作要区分系统自动、现场人员、主管确认。
- 反写、作废、补偿、重推必须有日志。
- 影响库存、成本、质量结论的数据要有审批或复核机制。

## 九、常见异常与排查

### 1. MES 显示已完工，金蝶生产订单没有更新

| 排查点 | 说明 |
| --- | --- |
| MES 回写日志 | 是否已发送，响应是否成功 |
| 幂等键 | 是否被判定为重复但原单未生成 |
| 金蝶源单状态 | 生产订单是否审核、下达、未关闭 |
| 工序匹配 | MES 工序编码是否能匹配金蝶工序 |
| 数量规则 | 是否超报、负数、合格数和不良数不合法 |
| 权限和组织 | 接口账号是否有对应组织和单据权限 |
| 插件和校验 | 是否有二开校验阻止保存或审核 |

处理方法：

1. 固定一张生产订单和一条 MES 报工流水。
2. 查 MES 发送报文、金蝶响应、金蝶接口日志。
3. 用同样数据在金蝶前台手工报工，判断是接口字段问题还是业务规则问题。
4. 如果金蝶已生成报工但 MES 未识别成功，按幂等键补同步状态，不要重复生成。

### 2. 设备自动数量和人工报工数量不一致

可能原因：

- 设备计数包含空跑、调机、试产、返工或不良品。
- 人工报工只报合格数。
- 设备点位重复触发或漏采。
- 班次跨天导致统计期间不同。
- MES 把设备原始数和业务确认数混在一起展示。

处理建议：

- 设备产量作为原始采集数，报工数量作为业务确认数。
- 看板同时展示“设备计数、报工合格数、报工不良数、差异数”。
- 差异超过阈值时要求班组长确认原因。
- 成本和完工入库以正式报工和入库单据为准。

### 3. 报工倒冲导致材料负库存

排查顺序：

1. 查生产订单用料清单是否正确。
2. 查线边仓、原材料仓、批号、库位是否有可用库存。
3. 查倒冲时点，是报工倒冲、完工倒冲还是入库倒冲。
4. 查替代料、补料、退料是否同步。
5. 查 WMS 或线边扫码是否已经出库但金蝶未过账。

处理建议：

- 对关键件和批号件优先扫码领料，不建议完全依赖倒冲。
- 对低值通用件可以倒冲，但要建立负库存预警。
- 月结前输出“倒冲失败、负库存、未领料已完工”清单。

### 4. 质量结果没有关联到报工或完工入库

常见原因：

- MES 只保存测试结果，没有回写金蝶检验单。
- 报工单号、批号、序列号缺失，导致检验结果无法关联。
- 质检在 MES 判定合格，但金蝶入库仍按未检状态。
- 返修后再次检验没有关闭原不良记录。

处理建议：

- 明确质量结论的主系统和最终生效点。
- 至少用生产订单号、工序、批号/序列号、报工流水号关联检验结果。
- 不良、返工、报废、让步接收必须有状态闭环。

### 5. 看板进度和实际在制品不一致

排查顺序：

1. 看板取的是 MES 工单状态、金蝶报工单、完工入库单还是 BI 汇总表。
2. 是否包含未审核报工、失败回写报工、返工和作废数据。
3. 生产订单变更、拆单、合单后看板是否重算。
4. 跨班次、跨日期、跨组织是否过滤一致。
5. 金蝶和 MES 是否有未对账差异。

处理建议：

- 看板要标明数据更新时间和来源系统。
- 订单进度用“计划数、开工数、报工数、完工入库数、差异数”分层展示。
- 每天固定时间输出 MES 与金蝶报工对账表。

## 十、上线验收清单

| 验收项 | 标准 |
| --- | --- |
| 主数据同步 | 物料、BOM、工艺路线、工作中心、设备、人员、仓库、批号编码可对齐 |
| 生产订单下发 | 金蝶生产订单能正确下发到 MES，变更和关闭有处理机制 |
| 报工回写 | 合格数、不良数、工时、工序、人员、设备能生成或更新金蝶记录 |
| 材料耗用 | 领料、补料、退料、倒冲能和库存、批号、线边仓对账 |
| 质量闭环 | 检验结果能影响返工、报废、让步、完工入库 |
| 完工入库 | 最后工序完成后，入库数量、仓库、批号、日期正确 |
| 幂等重试 | 超时、失败、重复推送不会重复生成业务单据 |
| 对账报表 | 有 MES 与金蝶订单、报工、入库、用料、检验差异表 |
| 看板可信 | 指标口径、数据来源、更新时间、异常阈值清楚 |
| 月结验证 | 报工、领料、完工、存货核算、制造成本能跑通 |
| 权限审计 | 接口账号、人工补偿、反写、作废、重推有日志 |
| 应急方案 | MES 故障、网络中断、设备离线时有离线报工和补录规则 |

本页用于把金蝶 ChatBI 从“听起来很智能”落到项目现场能执行的规则：问什么、怎么问、答案怎么解释、数字怎么复核、权限怎么管、上线怎么验收。

一句话理解：

```text
ChatBI 不是替代指标治理，而是把指标治理、数据模型和权限治理包装成业务人员能直接提问的入口。
```

如果指标字典混乱、主数据不干净、权限过宽、标准报表都对不平，ChatBI 只会更快地把混乱暴露出来。

## 一、资料来源与适用边界

公开资料显示，金蝶 ChatBI 被定位为“问数智能体”，强调从“看报表”转向“问数据”，通过自然语言对话生成可视化分析结果，并围绕统一口径、语义解析和结果解释提升经营分析效率。

## 二、ChatBI 解决什么问题

传统经营分析常见问题：

| 问题 | 传统处理 | ChatBI 目标 |
| --- | --- | --- |
| 临时取数慢 | 业务提需求，IT 或报表人员排期 | 业务直接用自然语言提问 |
| 口径沟通慢 | 反复确认含税、状态、日期、组织 | 自动关联已治理的指标口径 |
| 追问成本高 | 每追问一次都要新报表或新 SQL | 多轮问答继续下钻 |
| 看板固定 | 只能看预设图表 | 围绕当前问题即时生成图表或明细 |
| 解释缺失 | 数字给出来但不知道怎么算的 | 展示数据范围、公式、过滤条件和来源 |

注意：ChatBI 的关键不是“能聊天”，而是“能把聊天问题落到确定的数据主题、指标口径、维度和权限范围”。

## 三、ChatBI 的最小可用闭环

一套可上线的 ChatBI 至少需要六个部分：

```text
业务问题
  -> 指标字典
  -> 数据模型/语义层
  -> 权限范围
  -> 问答与可视化
  -> 解释、下钻、复核和行动
```

| 环节 | 要交付什么 | 常见失败 |
| --- | --- | --- |
| 业务问题 | 管理层和业务部门真正要问的问题清单 | 只把现有报表搬进来 |
| 指标字典 | 指标公式、来源、状态、日期、含税、币别 | 同名指标多口径 |
| 数据模型 | 事实表、维度、主题域和汇总策略 | 直接让模型猜底表 |
| 权限范围 | 组织、角色、客户、供应商、物料、金额敏感项 | 谁都能问利润和价格 |
| 问答体验 | 推荐问法、多轮追问、下钻、图表和明细 | 只能问非常固定的问题 |
| 复核治理 | 结果解释、抽样核对、日志和口径变更流程 | 数字错了无法定位原因 |

## 四、适合 ChatBI 的业务场景

### 4.1 经营总览

适合管理层每天或每周追问：

- 本月收入、毛利、净利润和现金流与预算差多少。
- 哪些事业部利润变差。
- 哪些客户贡献高但回款慢。
- 哪些产品销售增长但毛利下降。
- 费用超预算来自哪些部门和项目。

示例问法：

```text
按已审核销售出库单、不含税、本位币，统计 2026 年 6 月各事业部销售额、毛利额和毛利率，并列出同比下降最大的前 5 个产品线。
```

### 4.2 财务分析

适合财务、财务分析和经营分析岗位：

- 应收账龄和逾期客户。
- 预算执行和费用异常。
- 收入、成本、费用、利润桥。
- 现金流预测和资金占用。
- 合并口径和管理口径差异。

示例问法：

```text
按客户和销售组织列出截至 2026-06-30 的逾期应收余额，分 0-30 天、31-60 天、61-90 天和 90 天以上账龄段，并只显示逾期余额超过 10 万的客户。
```

### 4.3 供应链分析

适合采购、仓储、计划、供应链管理：

- 库存金额、库龄、周转和呆滞。
- 采购价格波动和供应商准交。
- 到货未开票、暂估和采购价差。
- 批号临期、库存状态和盘点差异。
- VMI、寄售和客户寄售库存消耗。

示例问法：

```text
列出库存金额前 20 且最近 90 天无出库的物料，按库存组织、仓库、物料分类和库龄分组，并标记是否已有未关闭采购订单。
```

### 4.4 销售和客户分析

适合销售负责人、渠道经理、客服：

- 客户贡献、客户毛利、回款质量。
- 销售订单、发货、退货、折让。
- 渠道售后、索赔和服务成本。
- 价格执行和信用风险。

示例问法：

```text
分析 2026 年 6 月华东区销售额下降的原因，按客户、产品线和销售员拆分，剔除退货红冲后列出影响最大的前 10 项。
```

### 4.5 制造分析

适合生产、计划、质量和制造成本：

- 计划达成率、完工入库、报工及时率。
- 工序瓶颈、良率、返工和报废。
- MES 回写差异和车间看板进度。
- 委外发料、入库和加工费。
- BOM 版本变更对订单和成本的影响。

示例问法：

```text
按生产订单统计本周计划完工、实际完工、未完工数量和延误天数，按车间、产品线和延误原因排序。
```

## 五、提问模板：从模糊问题变成可计算问题

很多 ChatBI 问答不准，不是 AI 不聪明，而是问题本身缺口太多。建议把问题写成这个结构：

```text
按[数据来源/业务口径]，在[组织/期间/状态/权限范围]内，
统计[指标]，按[维度]分组/排序/对比，
并输出[图表/明细/原因/行动建议]。
```

| 模糊问法 | 更好的问法 |
| --- | --- |
| 这个月销售怎么样 | 按已审核销售出库单、不含税、本位币，统计本月各销售组织销售额、毛利率和同比变化 |
| 哪些客户不好 | 列出逾期应收超过 30 天且余额超过 10 万的客户，展示责任销售、账龄段、最近回款日期 |
| 库存有没有问题 | 统计库存金额前 50 且 90 天无出库的物料，按库龄、仓库、物料分类和采购负责人展示 |
| 采购贵了吗 | 对比近 3 个月同物料不同供应商采购含税单价、到货准时率和退货率 |
| 费用超了多少 | 按预算版本和费用项目统计本月实际费用、预算、占用、可用余额和超预算原因 |

## 六、推荐问题库

### 6.1 管理层日问

| 问题 | 期待输出 |
| --- | --- |
| 昨天收入、毛利、回款和逾期应收有什么异常 | 异常摘要、环比变化、责任部门 |
| 本月利润低于预算的主要原因是什么 | 利润桥、收入/成本/费用拆解 |
| 哪些客户收入高但现金回款差 | 客户收入、回款、逾期、信用额度 |
| 哪些产品卖得多但毛利低 | 产品销量、收入、成本、毛利率 |
| 哪些库存金额高且周转慢 | 库龄、库存金额、最近出入库、采购计划 |

### 6.2 财务月结问法

| 问题 | 期待输出 |
| --- | --- |
| 本月销售出库未生成应收的单据有哪些 | 单据明细、客户、组织、金额、原因 |
| 本月采购入库未到票且金额较大的供应商有哪些 | 暂估余额、供应商、物料、库龄 |
| 总账收入和销售应收收入差异有哪些 | 法人口径、管理口径、差异分类 |
| 费用预算超支项目有哪些 | 部门、费用项目、预算、实际、占用 |
| 月末库存负数或异常成本有哪些 | 物料、仓库、数量、金额、异常类型 |

### 6.3 供应链问法

| 问题 | 期待输出 |
| --- | --- |
| 哪些供应商准交率下降 | 供应商、订单数、延期天数、影响物料 |
| 哪些采购价格近期上涨明显 | 物料、供应商、历史价格、涨幅 |
| 哪些销售订单已逾期未发货 | 客户、订单、物料、承诺日期、库存 |
| 哪些批号临期且库存金额高 | 批号、保质期、库存数量、金额 |
| 哪些 WMS 回写失败影响库存 | 接口批次、单据、错误、补偿状态 |

## 七、必须治理的指标口径

ChatBI 上线前，至少把 P0 指标做成指标字典。

| 指标 | 必填口径 |
| --- | --- |
| 销售额 | 订单、出库、应收、发票还是总账收入；含税/不含税；原币/本位币 |
| 毛利率 | 收入口径、成本口径、退货红冲、折让、标准成本/实际成本 |
| 回款率 | 收款单、核销、账龄截止日、预收和应收抵扣 |
| 逾期应收 | 应收余额、到期日、收款条件、核销状态、坏账准备 |
| 库存金额 | 即时库存、期间余额、可用库存、库存状态、存货核算金额 |
| 库存周转 | 销售成本、平均库存、期间长度、是否剔除样机/备件 |
| 采购价差 | 价格表、订单价、入库价、发票价、费用分摊 |
| 预算执行率 | 预算版本、占用、实际、释放、调整、审批状态 |

指标字典建议字段：

| 字段 | 说明 |
| --- | --- |
| 指标名称 | 业务用户看到的名字 |
| 指标编码 | 系统内唯一标识 |
| 业务解释 | 用非技术语言说明指标用途 |
| 计算公式 | 可复核的公式 |
| 数据来源 | 单据、报表、主题表或数据集 |
| 过滤条件 | 组织、状态、日期、币别、税额、退货 |
| 维度 | 组织、客户、供应商、物料、仓库、部门、项目 |
| 权限级别 | 普通、敏感、财务敏感、管理层敏感 |
| 负责人 | 口径 owner |
| 变更记录 | 版本、日期、原因、审批人 |

## 八、口径自动解释应该解释什么

ChatBI 的答案要能解释，否则业务人员只会更快地争论数字。

一条合格的回答，至少应说明：

| 解释项 | 示例 |
| --- | --- |
| 指标公式 | 毛利率 = 毛利额 / 销售额 |
| 数据来源 | 已审核销售出库单、存货核算成本、应收单 |
| 时间范围 | 2026-06-01 至 2026-06-30 |
| 组织范围 | 华东销售组织及其下级组织 |
| 状态过滤 | 已审核、未作废、剔除红冲单据 |
| 金额口径 | 不含税、本位币 |
| 权限范围 | 当前用户可查看的组织、客户、产品线 |
| 更新时间 | 数据集最后刷新时间 |
| 下钻入口 | 客户明细、产品明细、源单列表 |

如果答案只给一句“销售额 1000 万”，没有公式、来源、过滤条件和时间范围，这个结果不应进入正式经营会议。

## 九、权限和安全

ChatBI 比普通报表更敏感，因为自然语言降低了取数门槛。

| 风险 | 例子 | 控制 |
| --- | --- | --- |
| 越权看利润 | 销售员问全公司产品毛利 | 按组织、角色、指标权限控制 |
| 越权看价格 | 普通采购员问所有供应商价格 | 供应商/物料/价格敏感字段脱敏 |
| 越权看薪酬 | 业务用户问人员成本或绩效 | HR/薪酬指标单独授权 |
| 导出泄露 | 问答结果导出客户明细 | 导出权限、导出水印、日志 |
| 口径绕过 | 用户用换词绕过敏感指标 | 术语映射、敏感词、指标权限 |
| 外部传播 | 截图带出客户/价格/利润 | 展示脱敏、操作审计、培训 |

权限验收建议：

1. 用管理层、财务、销售、采购、仓库、普通员工六类账号分别测试。
2. 每类账号分别问收入、毛利、价格、客户、供应商、库存、薪酬等敏感主题。
3. 结果必须符合数据权限，不能因为“换一种问法”就越权。
4. 导出、复制、截图水印和日志要纳入审计。

## 十、ChatBI 和传统 BI 怎么分工

| 场景 | 固定报表 | BI 看板 | ChatBI |
| --- | --- | --- | --- |
| 法定报表 | 最适合 | 不适合替代 | 只能辅助解释 |
| 月结对账 | 最适合 | 可做监控 | 可问异常清单 |
| 管理驾驶舱 | 可做基础 | 最适合 | 可追问原因 |
| 临时经营问题 | 慢 | 中等 | 最适合 |
| 明细导出 | 最适合 | 可支持 | 要严控权限 |
| 指标治理 | 必须参与 | 必须参与 | 依赖治理结果 |

建议分工：

- 固定报表负责权威口径和法定口径。
- BI 看板负责常用管理场景、固定指标和趋势监控。
- ChatBI 负责临时追问、原因探索和业务人员自助分析。

## 十一、上线前数据准备清单

| 类别 | 检查项 |
| --- | --- |
| 主数据 | 组织、客户、供应商、物料、仓库、部门、项目是否完整 |
| 单据状态 | 草稿、提交、审核、关闭、作废、红冲是否定义清楚 |
| 日期口径 | 订单日期、出库日期、应收日期、发票日期、凭证日期 |
| 金额口径 | 含税、不含税、税额、折扣、折让、原币、本位币 |
| 成本口径 | 标准成本、实际成本、存货核算成本、制造成本 |
| 权限模型 | 用户、角色、组织、数据范围、敏感指标 |
| 数据刷新 | 实时、准实时、T+1、月结后刷新 |
| 对账基线 | 与标准报表、总账、存货核算、应收应付核对 |
| 术语映射 | 华东区、A 产品线、有效订单、逾期客户等业务词 |
| 样例问法 | 每个主题至少 20 个标准问法和 10 个反例问法 |

## 十二、验收矩阵

| 验收项 | 测试方法 | 通过标准 |
| --- | --- | --- |
| 指标口径 | 抽 10 个 P0 指标对照指标字典 | 公式、来源、过滤条件一致 |
| 标准报表核对 | 抽样同期间、同组织、同状态核对 | 差异能解释 |
| 权限隔离 | 用不同角色账号提相同问题 | 结果范围符合权限 |
| 多轮追问 | 从总览追问到客户、产品、单据 | 上下文不丢失，口径不漂移 |
| 口径解释 | 查看答案说明 | 能显示公式、来源、范围、更新时间 |
| 异常问题 | 故意问模糊问题 | 系统要求澄清，而不是乱答 |
| 性能 | 大期间、大组织、大维度问数 | 在可接受时间内返回或提示缩小范围 |
| 日志审计 | 查询敏感指标和导出 | 能追踪用户、时间、问题、结果范围 |
| 运营维护 | 修改一个指标口径 | 变更记录、审批、回归测试完整 |

## 十三、常见问题和处理

| 问题 | 典型原因 | 处理 |
| --- | --- | --- |
| 问出来的销售额和报表不一致 | 出库/应收/总账口径不同 | 固定数据来源和日期字段 |
| 毛利率不可信 | 收入口径和成本口径不匹配 | 建收入成本配对规则 |
| 同一个问题两次答案不同 | 数据刷新或权限上下文变化 | 显示刷新时间和权限范围 |
| 问“华东区”识别错 | 组织别名未维护 | 建业务术语和别名表 |
| 问“有效订单”争议大 | 业务部门定义不同 | 指标字典拆出销售有效、交付有效、财务有效 |
| 问题太宽导致慢 | 查询范围和维度太大 | 引导用户缩小期间、组织、维度 |
| 用户不信答案 | 缺解释和下钻 | 增加口径说明、明细列表和标准报表核对 |
| 用户问敏感数据 | 权限未细分 | 拆指标权限和字段脱敏 |

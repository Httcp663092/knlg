BI 不是“把 ERP 数据画成图”。真正有用的 BI，要能回答经营问题：

- 本月利润为什么变差？
- 销售额增长了，为什么现金没有变好？
- 哪些客户贡献利润，哪些客户占用资金？
- 哪些库存卖不动，为什么还在继续采购？
- 哪些供应商价格上涨，是否影响毛利？
- 生产效率下降，是订单结构、设备、报工还是物料齐套问题？

可以先记住一句话：

```text
报表回答“发生了什么”，BI 进一步回答“为什么、影响多大、下一步看哪里”。
```

## 一、BI 和普通报表的区别

| 对比 | 普通报表 | BI |
| --- | --- | --- |
| 主要用途 | 查询明细、固定格式输出 | 分析趋势、结构、异常和原因 |
| 使用对象 | 财务、业务专员、审计 | 管理层、业务负责人、分析人员 |
| 数据呈现 | 表格为主 | 指标卡、趋势图、结构图、明细下钻 |
| 口径要求 | 单张报表口径清楚 | 多指标、多主题统一口径 |
| 典型问题 | 这张单据多少金额 | 为什么毛利下降，哪个客户影响最大 |
| 维护重点 | SQL、字段、筛选条件 | 指标体系、数据模型、权限、迭代机制 |

普通报表是 BI 的基础。没有可靠的标准报表、单据状态和指标口径，BI 只会把错误放大成更漂亮的错误。

## 二、BI 的五层结构

```text
业务问题层
  -> 指标口径层
  -> 数据模型层
  -> 看板展示层
  -> 行动闭环层
```

| 层级 | 要回答的问题 | 常见产出 |
| --- | --- | --- |
| 业务问题层 | 管理者到底要决策什么 | 分析主题、会议问题清单 |
| 指标口径层 | 指标怎么算，按什么维度看 | 指标字典、口径说明 |
| 数据模型层 | 数据来自哪些单据和表 | 主题模型、宽表、明细层 |
| 看板展示层 | 怎么让用户看懂 | 驾驶舱、专题看板、明细下钻 |
| 行动闭环层 | 看完之后谁处理 | 异常清单、责任人、跟踪机制 |

## 三、先从业务问题设计 BI

不要从“做一张大屏”开始。要先问管理层和业务负责人：

| 角色 | 真正关心的问题 |
| --- | --- |
| 老板 / 总经理 | 利润、现金、增长、风险、异常项目 |
| 财务负责人 | 收入、成本、费用、预算、资金、月结质量 |
| 销售负责人 | 订单、发货、回款、毛利、客户贡献 |
| 采购负责人 | 采购价格、供应商交付、到票、暂估、价差 |
| 仓储负责人 | 库存准确率、呆滞料、周转、盘点差异 |
| 生产负责人 | 计划达成、报工、良率、设备效率、成本差异 |
| 售后负责人 | 退货、维修、备件、索赔、客户满意度 |

一个好 BI 主题要能写成这样的句子：

```text
为了让【角色】在【会议或场景】中判断【经营问题】，
需要按【组织、期间、产品、客户、渠道、项目】观察【指标】，
并能下钻到【单据或明细】找到责任和动作。
```

## 四、指标体系怎么搭

BI 不是指标越多越好。建议先按经营主线建指标树。

### 1. 经营结果指标

| 指标 | 看什么 | 常见维度 |
| --- | --- | --- |
| 收入 | 业务规模 | 组织、客户、产品、区域、渠道 |
| 毛利 | 赚钱能力 | 产品线、客户、订单、项目 |
| 净利润 | 综合结果 | 事业部、法人、期间 |
| 现金净流入 | 现金健康 | 银行账户、客户、项目 |
| 预算执行率 | 是否超预算 | 部门、费用项目、预算版本 |

### 2. 过程驱动指标

| 指标 | 看什么 | 影响 |
| --- | --- | --- |
| 订单交付率 | 是否按期交付 | 客户满意、收入确认 |
| 发货及时率 | 仓库和物流效率 | 销售履约 |
| 采购准交率 | 供应商交付 | 生产齐套、库存 |
| 到票及时率 | 供应商发票 | 应付、暂估、税务 |
| 生产计划达成率 | 计划执行 | 交期、成本 |

### 3. 风险控制指标

| 指标 | 看什么 | 风险 |
| --- | --- | --- |
| 逾期应收 | 客户回款风险 | 坏账、现金流 |
| 呆滞库存 | 库存积压 | 跌价、占用资金 |
| 负毛利订单 | 销售价格或成本异常 | 利润流失 |
| 超预算费用 | 内控风险 | 利润偏差 |
| 未审核单据 | 月结风险 | 报表不完整 |

## 五、指标字典模板

每个 BI 指标都要写清楚，不然上线后一定争口径。

```text
指标名称：
业务解释：
计算公式：
数据来源：
过滤条件：
统计期间：
组织口径：
金额口径：含税 / 不含税 / 本位币 / 原币
单据状态：暂存 / 已提交 / 已审核 / 已关闭
是否含退货：
是否含内部交易：
下钻路径：
负责人：
更新时间：
适用看板：
注意事项：
```

### 示例：销售收入

| 项目 | 示例口径 |
| --- | --- |
| 指标名称 | 销售收入 |
| 业务解释 | 已确认销售收入的金额 |
| 数据来源 | 应收单、收入确认单、销售出库或总账收入科目，按项目实际口径确定 |
| 金额口径 | 不含税、本位币 |
| 单据状态 | 已审核 |
| 是否含退货 | 扣减红字应收、销售退货和折让 |
| 下钻路径 | 组织 -> 客户 -> 产品 -> 订单 -> 应收/出库明细 |

同样叫“销售收入”，如果一个看板按销售出库统计，另一个看板按总账收入科目统计，数字很可能不同。BI 项目必须先统一口径，或者明确标出不同口径的用途。

## 六、金蝶 BI 常见数据主题

| 主题 | 主要来源 | 典型指标 |
| --- | --- | --- |
| 销售分析 | 销售订单、出库、应收、发票、收款 | 销售额、发货额、回款、毛利、客户贡献 |
| 采购分析 | 采购订单、入库、发票、应付、付款 | 采购额、准交率、价格波动、到票率 |
| 库存分析 | 即时库存、收发存、盘点、批号 | 库存金额、周转天数、呆滞料、库龄 |
| 财务分析 | 凭证、科目余额、应收应付、资金 | 利润、费用、现金流、预算执行 |
| 生产分析 | 生产订单、领料、报工、完工、质量 | 计划达成、良率、工时、成本差异 |
| 售后分析 | 退货、维修、备件、索赔 | 维修及时率、备件消耗、索赔金额 |
| 管理分析 | 事业部、产品线、客户、项目 | 事业部利润、产品毛利、客户贡献 |

## 七、BI 数据模型设计

BI 数据模型建议分三层理解。

| 层级 | 作用 | 示例 |
| --- | --- | --- |
| 明细层 | 保留可追溯业务明细 | 销售出库明细、应收明细、库存流水 |
| 汇总层 | 按固定粒度汇总 | 月度客户销售、物料库存月结、部门费用 |
| 指标层 | 给看板直接使用 | 毛利率、周转天数、预算执行率 |

不要一开始就只做大汇总表。没有明细层，用户问“为什么这个客户毛利下降”，就无法下钻到具体订单、物料、成本和折扣。

### 常见建模粒度

| 粒度 | 适合分析 |
| --- | --- |
| 组织 + 月 | 总体经营趋势 |
| 客户 + 月 | 客户收入、回款、贡献 |
| 产品 + 月 | 产品毛利、销量趋势 |
| 订单 + 分录 | 销售毛利、交付异常 |
| 物料 + 仓库 + 月 | 库存金额、周转、呆滞 |
| 供应商 + 物料 + 月 | 采购价格、交付质量 |
| 部门 + 费用项目 + 月 | 费用预算执行 |

## 八、BI 看板类型

| 看板 | 适合对象 | 内容 |
| --- | --- | --- |
| 老板驾驶舱 | 总经理、老板 | 收入、利润、现金、风险、异常 |
| 财务分析看板 | 财务负责人 | 利润、费用、预算、应收、现金流 |
| 销售分析看板 | 销售负责人 | 订单、发货、回款、毛利、客户 |
| 采购分析看板 | 采购负责人 | 采购额、价格、准交、到票、供应商 |
| 库存分析看板 | 仓库和供应链 | 库存、周转、呆滞、批号、盘点 |
| 生产分析看板 | 生产负责人 | 计划、报工、完工、良率、效率 |
| 异常预警看板 | 管理层和运维 | 超预算、逾期、负毛利、库存异常 |

## 九、老板驾驶舱建议结构

老板驾驶舱不要塞满图。建议第一屏只放能快速判断经营健康的指标。

| 区域 | 指标 |
| --- | --- |
| 经营结果 | 收入、毛利、净利润、预算完成率 |
| 现金风险 | 现金余额、经营现金流、逾期应收 |
| 资产占用 | 库存金额、呆滞库存、应收账款 |
| 业务增长 | 新增订单、发货金额、新客户、重点产品 |
| 异常清单 | 负毛利订单、超预算费用、逾期交付 |

下钻路径建议：

```text
集团总览
  -> 事业部 / 公司
  -> 产品线 / 客户 / 区域
  -> 订单 / 单据 / 凭证
  -> 责任人和处理动作
```

## 十、销售 BI 示例

销售 BI 不能只看销售额。销售额高但回款差、毛利低、退货多，经营质量仍然不好。

| 指标 | 说明 | 下钻 |
| --- | --- | --- |
| 销售订单金额 | 客户需求和销售规模 | 客户、产品、区域、销售员 |
| 发货金额 | 履约结果 | 出库单、仓库、交期 |
| 应收金额 | 客户欠款 | 应收单、账龄、信用 |
| 回款金额 | 现金回收 | 收款单、银行、核销 |
| 毛利率 | 赚钱能力 | 产品、订单、成本 |
| 退货率 | 质量和客户满意 | 退货原因、客户、产品 |

分析思路：

```text
销售额下降
  -> 看订单是否下降
  -> 看发货是否延迟
  -> 看客户结构是否变化
  -> 看产品价格是否下降
  -> 看退货和折让是否上升
```

## 十一、库存 BI 示例

库存 BI 要同时看数量、金额和周转。

| 指标 | 说明 |
| --- | --- |
| 库存金额 | 资金占用 |
| 库存周转天数 | 货卖动或用掉的速度 |
| 呆滞库存金额 | 长时间不动的库存 |
| 批号临期金额 | 有保质期风险的库存 |
| 盘点差异率 | 账实一致性 |
| 负库存次数 | 流程或时序风险 |

分析思路：

```text
库存金额上升
  -> 看销量是否下降
  -> 看采购是否提前或超量
  -> 看生产计划是否变化
  -> 看呆滞料是否增加
  -> 看寄售/VMI 是否纳入同一口径
```

## 十二、采购 BI 示例

采购 BI 要能回答“买得贵不贵、到得准不准、票来得及时不及时”。

| 指标 | 说明 |
| --- | --- |
| 采购金额 | 采购规模 |
| 采购价格波动 | 是否涨价或异常低价 |
| 供应商准交率 | 是否按期交付 |
| 到票及时率 | 发票和应付确认效率 |
| 采购价差 | 入库价、发票价、标准价差异 |
| 供应商集中度 | 是否过度依赖单一供应商 |

分析思路：

```text
采购成本上升
  -> 看采购价格变化
  -> 看供应商结构变化
  -> 看采购批量变化
  -> 看费用分摊变化
  -> 看暂估冲回和价差
```

## 十三、财务 BI 示例

财务 BI 要把法定口径和管理口径分清楚。

| 指标 | 法定口径 | 管理口径 |
| --- | --- | --- |
| 收入 | 按会计准则和凭证 | 可按事业部、产品线、区域重分类 |
| 成本 | 总账和存货核算 | 可按责任单元、订单、项目分摊 |
| 费用 | 科目和部门 | 可按预算项目、责任人、活动归因 |
| 利润 | 法人和合并报表 | 事业部、客户、产品贡献 |
| 现金流 | 现金流量表 | 回款、付款、资金预测 |

财务 BI 最怕两件事：

- 用业务报表数字替代财务确认数字，却不说明口径。
- 用总账科目数字做管理分析，却没有业务维度。

## 十四、BI 权限和数据安全

BI 权限比普通报表更敏感，因为它往往集中展示利润、成本、价格、客户、供应商和人员绩效。

| 权限点 | 说明 |
| --- | --- |
| 组织权限 | 用户只能看自己负责的组织 |
| 数据维度权限 | 销售只能看自己的客户或区域 |
| 指标权限 | 毛利、成本价、利润只给授权角色 |
| 明细下钻权限 | 能看汇总不代表能看单据明细 |
| 导出权限 | 敏感看板要限制导出 |
| 移动端权限 | 手机端查看同样要控制 |

上线前要做权限矩阵：

```text
看板名称
  -> 可见角色
  -> 可见组织
  -> 可见维度
  -> 是否可下钻
  -> 是否可导出
  -> 是否含敏感字段
```

## 十五、ChatBI 和自然语言分析

金蝶官网近年也在强调 AI 和 ChatBI 场景。自然语言分析的价值不是让用户少点几个按钮，而是降低业务人员理解数据模型和写查询的门槛。

适合问 ChatBI 或自然语言 BI 的问题：

| 问题 | 需要的底层准备 |
| --- | --- |
| 本月销售额为什么下降 | 销售订单、出库、应收、客户、产品口径 |
| 哪些客户毛利低 | 销售收入、出库成本、退货折让、客户维度 |
| 哪些库存呆滞 | 库存余额、出入库流水、库龄规则 |
| 哪些供应商涨价明显 | 采购价、物料、供应商、期间 |
| 本月预算超支在哪里 | 预算版本、费用项目、部门、实际发生额 |

注意：ChatBI 不是魔法。它回答得准不准，仍然取决于：

- 基础数据是否干净。
- 指标口径是否定义。
- 权限是否正确。
- 数据模型是否能追溯。
- 用户问题是否足够明确。

## 十六、BI 项目实施步骤

| 阶段 | 任务 | 产出 |
| --- | --- | --- |
| 1. 需求访谈 | 问管理层和业务负责人真正要决策什么 | BI 需求清单 |
| 2. 指标盘点 | 收集现有报表、Excel、会议材料 | 指标字典初稿 |
| 3. 口径确认 | 确认组织、期间、状态、金额、退货、内部交易 | 口径确认表 |
| 4. 数据梳理 | 找单据、表、接口和维度来源 | 数据来源清单 |
| 5. 模型设计 | 明细层、汇总层、指标层 | 主题模型 |
| 6. 看板设计 | 布局、筛选器、下钻路径 | 原型图 |
| 7. 数据校验 | 和标准报表、总账、业务明细核对 | 校验记录 |
| 8. 权限配置 | 角色、组织、维度、导出 | 权限矩阵 |
| 9. 上线试运行 | 收集反馈、修口径、修展示 | 试运行报告 |
| 10. 持续运营 | 月度复盘、指标治理、看板淘汰 | BI 运维机制 |

## 十七、BI 验收清单

- [ ] 每个指标都有指标字典。
- [ ] 每个看板都有目标用户和业务场景。
- [ ] 每个金额指标说明含税、不含税、本位币、原币。
- [ ] 每个业务指标说明单据状态和日期口径。
- [ ] 关键指标能下钻到明细单据。
- [ ] 和标准报表、总账、业务明细抽样核对。
- [ ] 权限矩阵已由业务负责人确认。
- [ ] 敏感字段、成本、毛利、利润和导出权限受控。
- [ ] 有异常清单和责任人，不只是展示图表。
- [ ] 有月度口径变更记录。

## 十八、常见问题

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 看板数字和报表不一致 | 口径不同 | 写清数据来源、期间、状态、退货、税额 |
| 老板觉得图很多但没用 | 没从业务问题出发 | 改成经营问题和异常清单驱动 |
| 用户不信 BI | 没有和标准报表抽样核对 | 建校验记录和下钻链路 |
| 毛利分析不准 | 收入和成本口径不一致 | 统一订单、出库、应收、成本结转关系 |
| 库存周转不准 | 库存金额、销售成本、期间口径混乱 | 固定计算公式和统计周期 |
| 权限过宽 | 直接给全员看板 | 按组织、角色、维度、指标拆权限 |
| 每月都改口径 | 指标没有治理人 | 建指标变更流程和版本 |

## 十九、推荐 BI 指标清单

| 主题 | P0 指标 | P1 指标 |
| --- | --- | --- |
| 经营总览 | 收入、毛利、净利润、现金、逾期应收 | 事业部利润、客户贡献、产品贡献 |
| 销售 | 订单、发货、应收、回款、毛利 | 客户画像、成交周期、退货率 |
| 采购 | 采购额、采购价差、准交率、到票率 | 供应商评分、集中度、价格趋势 |
| 库存 | 库存金额、周转天数、呆滞库存 | 批号临期、库龄结构、盘点差异 |
| 财务 | 费用、预算执行、现金流、应收账龄 | 费用预测、利润桥、资金预测 |
| 生产 | 计划达成、完工、报工、良率 | 设备效率、工序瓶颈、成本差异 |
